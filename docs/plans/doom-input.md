# Doom: починить ввод в QEMU (отложено)

**Статус:** сломано, работу остановили 13 августа 2026 — несколько кругов
правок не дали играбельный ввод. Не трогать «ещё одну гипотезу» без новых
фактов (логи `kbdvirt` / гостя).

## Симптом

В QEMU (`argon run -Gfx -Sd -Virt`, `virt`, `run a:\doom.axe -iwad a:\doom1.wad`)
клавиши **теряются целиком**: нельзя даже стартовать с титра (Enter / стрелки).
Раньше бывало «залипание» (down дошёл, up нет). После правок стало хуже.

## Что уже пробовали (и это не закрыло баг)

- Фокус-follow в `tools/kbdvirt.py` (точное hwnd, потом `GetAncestor` /
  SDL-child, пропуск консолей, RCtrl sticky).
- Очередь клавиш в госте: 32-слот FIFO → bitmap held/posted/tap → снова FIFO 128.
- Не поллить kbd во время blit; мышь не слать в меню/титр.
- WASD + mouse-look (`1662fab`), OPL3-музыка (`f613f7f`).

Музыка/SFX — отдельная тема; блокер сейчас **клавиатура**.

## Когда вернёмся

Нужны улики, не очередной рефактор:

1. Пишет ли хост `capture ON` в `build/virt.out.log` при клике по RGB QEMU?
2. Доходят ли пакеты до `KBDVIRT.SYS` / `AG_EV_KEY_*` в Doom?
3. Если хост молчит — ломать захват Windows; если хост шлёт, а меню мёртвое —
   `DG_GetKey` / `I_GetEvent` / мышь, съедающая титр.

Код: `tools/kbdvirt.py`, `apps/kbdvirt/`, `apps/doom/port/doomgeneric_argon.c`,
`apps/doom/core/i_input.c`.
