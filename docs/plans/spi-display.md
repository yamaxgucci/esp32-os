# Задача: подключить ещё один дисплей по SPI

Карточка для отдельного чата. Всё, что нужно знать, — здесь; читать историю
другой сессии не требуется.

## Что уже есть, и это надо использовать, а не писать заново

**`apps/ili9341/ili9341.c` — рабочий драйвер SPI-панели, загружаемый `.SYS`.**
Это образец, с которого нужно начинать. Он:

- объявляет себя через `AG_DRV("ILI9341", "0.5", "argon")` и появляется в `dev`
  как `lcd0  display  ILI9341`;
- **владеет панелью от загрузки до выгрузки** — пины, подсветка,
  инициализация. Это принципиально: до него была программа `apps/lcd`, которая
  рисовала кадр и завершалась, а завершение отдавало пин подсветки обратно, и
  экран гас через миллисекунду;
- **не держит кадровый буфер вообще**: 320×240 в RGB565 — это 150 КБ, а у той
  платы нет PSRAM. Вместо этого ядро отдаёт консоль **символами** (`text_row`,
  ABI 0.27), а драйвер превращает строку символов в пиксели в буфере на 5 КБ.
  Строка — это одна команда окна и 320×8 пикселей по SPI, около двух
  миллисекунд, и посылаются только изменившиеся строки.

**`apps/remdisp/remdisp.c` — второй драйвер дисплея**, для сравнения: он
передаёт настоящие пиксели (`blit_rect`, ABI 0.30) по UART на вторую плату, с
палитрой и передачей только изменившихся блоков.

## Контракт драйвера дисплея (`ag_display_ops_t`, `sdk/include/argon/abi.h`)

Два разных пути, и выбор между ними — первое решение задачи:

- **`text_info` / `text_row` / `text_cursor`** (ABI 0.27) — консоль как
  символы. Для панели, на которую кадровый буфер не влезает. Дёшево, но
  показывает только текст.
- **`blit_rect`** (ABI 0.30) — прямоугольник пикселей, которым владеет
  вызывающий. Драйвер размещает его на панели с целочисленным масштабом, по
  центру. Ничего по дороге не копируется. Это нужно, если на экране должна
  быть графика (игра, `gfxdemo`).

Драйвер может реализовать оба.

## Что надо спросить у Максима до начала

1. **Какой именно дисплей** — контроллер (ILI9341 / ST7789 / ST7735 / SSD1306 /
   другой), разрешение, интерфейс (4-wire SPI?), есть ли подсветка на отдельном
   пине.
2. **К какой плате** он подключается. Их две и они заняты разным:
   - **ESP32-S3, COM4** — на ней идёт Fallout 2, 8 МБ PSRAM, из них 6000 КБ
     отданы игре под арену. Свободной памяти после запуска игры почти нет.
   - **ESP32 «CYD», COM3** — сейчас работает как удалённый экран и динамик для
     S3 по UART (принимает картинку от REMDISP). У неё **нет PSRAM**.
3. **Какие пины** — SPI-шина, CS, DC, RST, BL. Драйвер **не может прочитать
   BOARD.CFG** (`api->cfg` в драйвере равен NULL), поэтому пины в нём —
   константы, и неверная константа дёргает чужой пин. См.
   `docs/03-board-config.md`.
4. **Что на нём показывать** — консоль (тогда `text_row`, как ILI9341) или
   картинку (тогда `blit_rect`).

## Как это собирается

Драйвер — это `.SYS`, собранный `tools/mkaxe.py`; запись о нём лежит в
`tools/apps.json` (см. там `ili9341`). Пример сборки — в шапке
`apps/ili9341/ili9341.c`:

```
python tools/mkaxe.py --arch xtensa --gcc xtensa-esp32-elf-gcc \
    --include sdk/include --include apps/common \
    -o build/apps/ILI9341.SYS apps/ili9341/ili9341.c
```

Загрузка на плате: `drv load a:\<имя>.sys`, проверка — `dev`.

## Правила этого проекта, которые тут применяются

- **Прошивка минимальна.** Новый дисплей — это загружаемый `.SYS`, а не код в
  образе. Не встраивать.
- **Ядро не знает про ESP-IDF.** Всё, что трогает железо, идёт через
  `components/argon_port`; в драйвере — через ABI (`api->io->spi_*`).
- **Проверка**: хостовые тесты плюс QEMU — это ворота; плата отвечает только на
  то, чего QEMU не может (реальный SPI и есть такой случай).
- **Инструменты запускаются из PowerShell**: `argon.cmd` — точка входа, из Bash
  он не работает. Python — `D:\dev\python312\python.exe` (голый `python` это
  заглушка из Store, выходит с кодом 49).
- **Плата занята.** На S3 сейчас идёт игра, на CYD — её экран. Перед работой
  спросить, можно ли забирать плату, и не писать в консоль во время игры:
  консоль делит провод с картинкой.

## Чего это касаться не должно

Fallout, REMDISP и USB-мышь трогать не нужно — они в другой работе. Если
кажется, что нужно, это повод спросить, а не менять.
