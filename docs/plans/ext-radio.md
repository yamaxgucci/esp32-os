# Внешнее радио — драйвером, а не сборкой

**Статус:** в работе (ветка `ext-radio`), начато 1 сентября 2026. Цель первого
захода — довести всё, что проверяется **без плат**, до зелёного в QEMU; железо
подключается в конце.

## Замысел (согласовано с Максимом)

Радиомодуль (Wi-Fi, GSM/LTE, sub-GHz…) на UART/SPI — это «чип на шине», то есть
загружаемый `.SYS`, ровно как панель дисплея или сенсор камеры (доктрина
фазы 4.5). Внешнее радио — **альтернатива, а не замена** встроенному: обе
подсистемы остаются в сборке, работает одна за раз. Приоритет Максима:
**максимум возможностей и гибкости при минимуме раздутия образа**. Главный рычаг
против раздутия — тот же механизм: он позволяет собрать образ **без** встроенного
радио и получить сеть снаружи по проводу (−616 КБ флеша, +~50 КБ internal SRAM).

Абсолютная гибкость достигается **привязкой по способностям, а не по чипу**: у
системы уже есть раздельные поверхности `net` (сокеты), `wifimon` (кадры),
`espnow` (датаграммы), `ble`. Внешний `.SYS` объявляет, какие из них он
заполняет. «AT-подобный или Hosted-подобный» — это **внутреннее дело `.SYS`**:
один реализует сокеты через AT-команды, другой через Hosted-фрейминг; выше
драйвера разницы нет.

## Что показала разведка по коду

1. **У порта два потребителя.** Путь ABI идёт через таблицу хэндлов в
   `net.c`, но `netio.c`/`httpc.c`/`ftpc.c`/`ssh.c`/`mqtt.c`/`modbus.c`/
   `telnet_console.c` зовут `ag_port_net_*` напрямую на сырых `int` fd. Развязка
   обязана покрыть **оба** пути, иначе сокет, открытый через внешний провайдер,
   уйдёт на чтение во встроенный.
2. **Порт выбирается на этапе сборки, рантайм-развязки нет.** `ag_port_net_*` —
   прямые extern-символы, реализованы в `idf/src/net_hw.c` поверх `lwip_*`.
3. **`AG_DEV_NET` — мёртвый enum.** Класс есть в перечислении и в
   `ag_dev_class_name`, но **ни один vtable его не потребляет**: `.SYS`,
   зарегистрировавший `AG_DEV_NET`, в сокет-стек не встраивается. Значит развязку
   надо строить в ядре — это и будет **первый живой `dev->ops`-класс** (в доке
   драйверов прямо сказано «остальные классы со своими vtable ещё впереди»).
4. **HostFS — точный шаблон** для «Python на хосте ↔ гостевой драйвер по UART»:
   `hsfs_proto.h` (framed header magic+seq+len), `hostfsd.py` (TCP-сервер,
   `struct.pack`, поток непрошеных PADPUSH), `hostfs.c` (UART1, mutex-`rpc()`,
   глотание непрошеных кадров). UART2 (индекс 2) свободен, QEMU его эмулирует
   (`SOC_UART_NUM=3`), добавляется третьим `-serial`.

## Единственный активный провайдер

Модель — «одно радио за раз», как и сам встроенный Wi-Fi (`wifi on/off`). Это
снимает почти все сложности одновременных интерфейсов (общий `s_got_ip`,
единственный `on_ready`, коллизии fd). Переключение провайдера — админское
действие уровня `wifi off`: открытые сокеты закрываются, как при опускании линка.
Мультиплекс двух интерфейсов одновременно — **не** в этой фазе.

## Слои (что где строится)

```
приложение / шелл-команды (wget, ftp, ssh, mqtt, modbus, httpd…)
        │  вызывают ag_port_net_* (без изменений в вызовах)
        ▼
ag_netprov_*   ← НОВОЕ. Диспетчер: зовёт активный провайдер.
   src/net/netprov.c + include/argon/netprov.h
        │
        ├─ встроенный провайдер (по умолчанию) → ag_port_net_* → lwIP  (не тронут)
        └─ внешний провайдер = ag_net_ops_t устройства AG_DEV_NET
                 ▲
      apps/extradio/extradio.c  (.SYS): io->uart(2) ↔ протокол RLINK ↔ сопроцессор
                 ▲
      RLINK-кодек: apps/common/rlink/ag_rlink.{c,h}  (чистая логика, host-тесты)
                 ▲
      tools/rlinkd.py  (фиктивный сопроцессор на 3-м -serial QEMU)
```

**Точка врезки — `ag_port_net_*` → `ag_netprov_*`.** Все ~62 вызова в ядре
(оба потребителя) механически переименовываются в `ag_netprov_*`. Диспетчер
держит `const ag_net_ops_t *s_active`; по умолчанию — статический встроенный
провайдер-обёртка над `ag_port_net_*` (порт `idf` не трогаем). `net use <dev>`
подменяет активный на `ag_net_ops_t` устройства `AG_DEV_NET`.

TLS/`https` поверх внешнего радио — **вне этой фазы**: `esp_tls` оборачивает
lwIP-сокет и внешний не увидит. Когда внешнее радио активно, `https` просто не
предлагается (как сегодня при выключенном TLS). Модем со своим TLS или
портируемый mbedTLS-над-провайдером — потом.

## Контракт `ag_net_ops_t` (ABI 0.42, append-only)

Зеркало 15 функций порта, но с `ag_device_t *dev` первым аргументом (провайдер
достаёт своё состояние через `ag_dev_priv(dev)`). `on_ready` убран: ядро само
опрашивает `ready()` и печатает `ifaddr()` при появлении адреса.

```c
typedef struct ag_net_ops {
    uint32_t size;
    ag_err_t (*start)(ag_device_t *dev);
    bool     (*ready)(ag_device_t *dev);
    ag_err_t (*ifaddr)(ag_device_t *dev, uint32_t *addr);      /* host-order */
    ag_err_t (*resolve)(ag_device_t *dev, const char *host, uint32_t *addr);
    int      (*listen)(ag_device_t *dev, uint16_t port);
    int      (*accept)(ag_device_t *dev, int lfd, uint32_t timeout_ms);
    int      (*connect)(ag_device_t *dev, uint32_t addr, uint16_t port,
                        uint32_t timeout_ms);
    int32_t  (*send)(ag_device_t *dev, int fd, const void *buf, size_t len);
    int32_t  (*recv)(ag_device_t *dev, int fd, void *buf, size_t len);
    void     (*net_close)(ag_device_t *dev, int fd);
    ag_err_t (*nonblock)(ag_device_t *dev, int fd, bool on);
    int      (*wait_readable)(ag_device_t *dev, int fd, uint32_t timeout_ms);
    int32_t  (*recv_now)(ag_device_t *dev, int fd, void *buf, size_t len);
} ag_net_ops_t;
```

Драйвер публикует его как `class_ops` в `ag_dev_add` для `cls = AG_DEV_NET`.

## RLINK — протокол на проводе (гость ↔ сопроцессор)

Framed, little-endian, как HSFS. Заголовок фиксированной длины + payload.
Запрос/ответ по `seq` под мьютексом; непрошеные `DATA`/`EVENT` от сопроцессора
глотаются вне транзакции (принятые байты буферизуются по каналам — так `recv_now`
отвечает «что уже пришло» без похода к сопроцессору, чего требует `netio.c`).
Текст протокола (кодек) отделён от транспорта и покрыт host-тестами — как
`netmsg.c`. Полная спецификация — в шапке `apps/common/rlink/ag_rlink.h`.

## Сделано и проверено в QEMU (1 сентября 2026)

Весь тракт работает без единой платы. `argon rlinktest`
([`tools/rlinktest.ps1`](../../tools/rlinktest.ps1)) грузит `EXTRADIO.SYS`,
делает `net use extradio` и тянет файл с `netfixture` **через внешнее радио** —
8 проверок, 0 отказов: рукопожатие RLINK (`coprocessor proto 1`), привязка
провайдера (`network is via extradio`), DNS через радио, `wget`
(`hello from the host`), chunked. `argon nettest` (встроенный провайдер) —
**45/45**, то есть развязка ничего не сломала: http, https/TLS, ftp, dns идут
как шли. `argon tests` — RLINK-кодек и всё остальное зелёное.

- **M1** RLINK-кодек + host-тесты — сделано.
- **M2** `ag_net_ops_t` (ABI **0.42**, не 0.39 — версия ушла вперёд) +
  `netprov.c/.h` + переименование ~62 вызовов + `net use` — сделано; образ вырос
  на **1 584 Б** (1 000 768 → 1 002 352).
- **M3** `apps/extradio/extradio.c` — сделано. **Без фоновой задачи**: у `.SYS`
  в `ag_driver_init` нет текущего процесса, и `api->task->create` его
  отвергает; поэтому модель HostFS — UART качается inline из `rpc()` и recv-
  операций, один мьютекс на всё.
- **M4** `tools/rlinkd.py` (реальный TCP-прокси) + `-Radio` в `qemu-boot.ps1` +
  `argon rlinktest` — сделано.

### Грабли, на которые наступили (и что из них вышло в общий код)

1. **QEMU esp32s3 эмулирует только UART0 и UART1.** UART2 (куда «правильно»
   вешать радио на железе) в эмуляторе не отдаёт данные — TCP-чардев
   подключается, а регистры молчат. Поэтому в QEMU радио живёт на **UART1**, и
   драйвер сам выбирает UART1 на плате `generic` (это и есть QEMU), UART2 —
   иначе; переопределяется ключом `radio.uart`. HostFS тоже хочет UART1, так что
   в QEMU `-Radio` и `-HostFs` несовместимы — `.SYS` в тесте приезжает через
   `-Put` (консоль), не через HostFS.
2. **`ag_port_uart_config` конфигурировал UART из неинициализированного
   `uart_config_t`** — `rx_flow_ctrl_thresh` был мусором со стека, и
   `uart_param_config` падал с «rx flow thresh error». HostFS это не задевало
   только потому, что его стек оказывался нулевым. Починено в порту
   ([`uart_hw.c`](../../components/argon_port/idf/src/uart_hw.c)): поле
   выставляется, структура зануляется. Это латентный баг всего UART-порта, не
   только радио.
3. **Слой `io` переконфигурировал UART на каждом чтении/записи** —
   `uart_bring_up` звал `ag_port_uart_config` + `ag_port_uart_pins` всегда, а не
   только при подъёме. Для потока это и накладно, и опасно (сброс делителя
   посреди кадра). Починено ([`io.c`](../../components/argon_kernel/src/dev/io.c)):
   конфигурируем при подъёме и по явному `io_uart_config`, обычное чтение — нет.
4. **`io`-UART требует пины из BOARD.CFG даже в QEMU.** Профиль `generic`
   теперь несёт заглушечные пины UART1/UART2 ([`board.c`](../../components/argon_kernel/src/boot/board.c));
   эмулятор их игнорирует, реальная плата задаёт свои.

## AT-вариант — родная прошивка ESP-01 (сделано)

Второй backend, «и тот и другой по необходимости»: тот же `ag_net_ops`, но
поверх **заводского AT** ESP-01, а не нашего RLINK. Первый результат на железе
без перепрошивки — только провод.

- **AT-кодек** `apps/common/atproto/ag_atproto.{c,h}` (freestanding, как rlink:
  ни snprintf/strncmp/strchr, ни strcmp/ag_strcmp — свои `streq`/`sb_*`, только
  `strlen` общий). Классификация строк (`OK`/`ERROR`/`SEND OK`/`>`/
  `<n>,CONNECT`/`<n>,CLOSED`/`+CIPDOMAIN`/`+CIFSR`/`+CIPSTA`) и разбор `+IPD`
  (mux/single, вложенный, неполный хвост, префикс тега на границе). Host-тесты
  в стиле `test_rlink`: `host-tests/test_atproto.c` (в `argon tests`).
- **`ATRADIO.SYS`** `apps/atradio/atradio.c`: AT-команды вместо RLINK-rpc,
  кольца по каналам питаются `+IPD` (стримом, payload не держим в буфере),
  ловля голого `> `-промпта без перевода строки. `listen`/`accept` →
  `-AG_ENOTSUP` (серверная модель AT другая; клиентских сокетов хватает wget/
  ftp/ssh). Join по `radio.ssid`/`radio.pass`; без них модем считается уже
  подключённым (фикстур/провижининг снаружи).
- **Фиктивный AT-модем** `tools/atmodemd.py` — как `rlinkd.py`, но говорит AT и
  проксирует в реальные сокеты. `argon attest` (`tools/attest.ps1`,
  `qemu-boot -RadioScript atmodemd.py`) — **8/8** в QEMU: `net use atradio` →
  скачать файл через AT-радио, встроенного в тракте нет.

AT покупает только сокеты: ни monitor mode, ни ESP-NOW, ни инжекта — за этим
RLINK. TLS/https поверх AT — как и у RLINK, вне тракта (TLS в порту).

## Прошить ESP-чип самой платой — `ESPFLASH.AXE` (в работе)

Задача Максима (12 сентября 2026): чтобы поставить на модуль нужную прошивку
(заводской AT для `atradio`, наш будущий сопроцессор для `rlink`, что угодно), не
нужен отдельный USB-UART. **Плата прошивает модуль сама**, читая готовый `.bin` с
диска (A:/C:/H:). esptool на ПК в этом варианте только *делает* бинарник
(`elf2image`/`merge_bin`) или его просто скачивают; сам протокол загрузки гоняет
ArgonOS.

Максим попросил максимум чипов. **Весь протокол загрузки одинаков у всего
семейства** ESP (ESP8266 и ESP32/S2/S3/C3/C6/C2/H2) — SLIP-кадры и команды те же.
Различия чипа маленькие и лежат таблицей в шапке `espflash.c`: длина хвоста-
статуса в ответе (ESP8266 — 2 байта, ESP32-семейство — 4), нужен ли `SPI_ATTACH`
до записи (ESP32+ — да), как считать стирание (квирк ESP8266 против «ровно
регион»), и magic-значения регистра опознания. Чип определяется **сам** после
SYNC (чтение `0x40001000` и сверка с таблицей) или задаётся `-chip <имя>`.
Стоимость всего семейства в образе: `.AXE` вырос с 3756 до **4128 байт** кода —
это данные таблицы плюс `SPI_ATTACH`. Один `.AXE`, никаких доп. модулей, провод и
питание те же; у разных чипов лишь другие имена ног download-режима и условие
страпа. Проверены на железе будут ESP8266 и ESP32 (чип на C6/старых платах);
остальные профили — по спецификации esptool, до модуля на столе. Чипы, которые
esptool различает не этим регистром, а запросом security-info (часть новых
C-серий), автоопределение не ловит — их называют через `-chip`.

**Почему это не «прозрачный мост» и почему так проще.** Первая мысль была —
превратить плату в прозрачный USB↔UART: esptool на ПК говорит по проводу сквозь
плату прямо с ROM-загрузчиком модуля. Но это требует **отдать консольный UART0
приложению**, а слой `io` его не отдаёт намеренно (`io.c`: `-AG_EBUSY` на
`AG_PORT_UART_CONSOLE`) — пришлось бы городить «сырой проход консоли» в ядре, и
на время прошивки консоль умирала бы. UART1 же **не консоль**, и `io` отдаёт его
приложению без единой правки ядра. Поэтому прошивальщик — обычный **`.AXE`**
(доктрина «минимум в образе»: тула ставится, когда нужна, а не лежит в прошивке),
а консоль во время работы жива и показывает прогресс.

Путь **no-stub**: весь протокол — команды ROM ESP8266 (медленнее stub'а esptool,
зато без второго бинарника-загрузчика в RAM).

- **Кодек** `apps/common/esp8266/ag_espldr.{c,h}` (freestanding, как rlink):
  SLIP-кадрирование (C0/DB и экранирование), заголовок команды 8 Б
  (`dir,cmd,size,cksum`) + данные, разбор ответа и его **двухбайтовый статус**
  ROM, контрольная сумма блока (seed 0xEF), payload SYNC и **квирк erase-size**
  ESP8266 (`get_erase_size` из esptool — иначе хвост образа не стирается).
  Host-тесты `host-tests/test_espldr.c` (в `argon tests`).
- **`ESPFLASH.AXE`** `apps/espflash/espflash.c`: таблица чипов, UART через `io`
  ABI, файл через `fs`, необязательный сброс в download через `io->gpio`.
  Команды:

  ```
  espflash id    [-c ЧИП] [-p ПОРТ] [-b БОД] [-r GPIO0 RST]
  espflash write <файл> [-a АДРЕС] [-c ЧИП] [-p ПОРТ] [-b БОД] [-r GPIO0 RST]
  ```

  По умолчанию порт 1 (UART1), бод 115200, адрес 0, чип `auto`. `id`
  опознаёт чип (magic `0x40001000`) и, для ESP8266, печатает слова MAC —
  проверка двусторонней связи без записи флеша.

### Как физически подключить и прошить (CYD)

- ESP-01 на UART1 CYD: `[uart1] tx=22 rx=21` в `C:\BOARD.CFG` (**крест**:
  IO22→RXD модуля, IO21→TXD модуля), VCC/GND с CN1, CH_PD на 3.3 В.
- **Вход в download-режим руками** (на CYD свободных ног нет, GPIO0/RST модуля не
  разведены): перемычка **GPIO0→GND**, затем **передёрнуть питание** модуля, и
  только потом запускать команду. Бод обоих концов держать равным (`-b`).
- На плате: положить бинарник на карту/флеш/хост и
  `run a:\espflash.axe write a:\at.bin` (или сперва `... id` — убедиться, что
  модуль отвечает). Полоса прогресса идёт в консоль; в конце FLASH_END с
  reboot=0 — модуль стартует новую прошивку.

### Автосброс в download (сделан, на CYD выключен)

Ключ `-r GPIO0 RST` гонит классическую последовательность esptool прямо на пины
модуля (обе линии активны низким): держим в reset при GPIO0=1, отпускаем reset
при GPIO0=0 (ROM защёлкивает download), затем отпускаем GPIO0. На CYD ног нет —
ключ не задаётся, вход руками; **на других платах со свободными ногами** просто
передать пины, и сброс/питание не трогать руками. Это ровно требование Максима:
автосброс есть, на CYD он выключен.

### Проверяемость и что дальше

- Без железа: кодек — host-тестами; сборка `ESPFLASH.AXE` — `argon apps`. Сам
  протокол отвечает только живой модуль (SYNC/`id`/`write`) — это шаг на плате.
- **STM32 — отдельный инструмент `STM32FLASH.AXE`** (сделан, кодек host-тестами):
  протокол ST AN3155, линия **8E1**, вход в загрузчик по BOOT0=высокий. Другой
  протокол — поэтому отдельный `.AXE`, общий с espflash только UART и файл. Кодек
  `apps/common/stm32/ag_stm32ldr.{c,h}`, `host-tests/test_stm32ldr.c`. Инструкция
  пользователя — [`docs/user/06-flashing-a-coprocessor.md`](../user/06-flashing-a-coprocessor.md).
  AVR (STK500) — при необходимости следующим тем же образом; **RP2040 по UART
  прошить нельзя** (нет UART-загрузчика в ROM, только USB).
- **Вариант 2 — прозрачный мост (сделан):** команда ядра `uartbridge <порт>
  [бод]` снимает UART0 с консоли и гонит UART0↔UARTn **сырьём до перезагрузки**,
  превращая плату в прозрачный USB-UART. Тогда esptool (или что угодно) на ПК
  говорит с чипом **напрямую через плату**. Реализация: `ag_uart_console_detach`
  снимает эндпоинт (драйвер порта остаётся), затем бесконечный цикл копирует обе
  стороны; консоль на время моста молчит намеренно (единственный выход — reset).
  **Важно:** DTR/RTS-автосброс esptool дёргает *эту* плату (так её саму и
  прошивают), а не дальний чип, — поэтому на ПК `--before no_reset --after
  no_reset`, а дальний чип в download вводится отдельно. См.
  [`docs/user/06-flashing-a-coprocessor.md`](../user/06-flashing-a-coprocessor.md).
  Отличие от `ESPFLASH.AXE`/`STM32FLASH.AXE`: там плата — прошивальщик и читает
  `.bin` с диска; здесь плата — только провод, а протокол гоняет ПК. Мост
  универсален (любой протокол, любой чип), но занимает консоль; свои флешеры
  оставляют консоль живой и не нужен ПК с esptool.
- **Дальше в самом `espflash`:** чтение SPI flash-id (производитель/размер) через
  дёрганье SPI-регистров (`WRITE_REG`/`READ_REG`), опциональная верификация
  записанного, RAM-stub для скорости.
## Ввод в строй на железе (2026-09-13): ESP-07 + баг `api->cfg == NULL`

Первый рабочий внешний модем — **ESP-07** на стоковой AT-прошивке, припаян к
**CYD** (esp32/LX6, COM7) на UART1 (`tx=22`, `rx=21`, кроссовер). Модуль сразу
отвечал на AT (`atbaud` → `115200: OK`), `ATRADIO.SYS` печатал «modem answers AT
on uart1», но `net use atradio` давал `address 0.0.0.0` и в сеть не выходил.

Диапазон (сеть 2.4 ГГц), пароль и разбор ответа `CIFSR` оказались **ложным
следом**. Отладочная сборка `atradio` (лог результата CWJAP + строки CIFSR)
показала `no radio.ssid - not joining`, хотя в `C:\SYSTEM.CFG` секция `[radio]`
с `ssid`/`pass` присутствовала (проверено `type c:\SYSTEM.CFG`).

**Первопричина — в ядре, не в радио.** В ABI-таблице
(`components/argon_kernel/src/loader/api.c`) поле `.cfg` было `NULL` и никогда не
заполнялось: реализации `ag_cfg_api_t` не существовало вовсе. Поэтому
`ag_api()->cfg` был `NULL` для **любого** `.SYS`/`.AXE`, `AG_HAS(cfg, get_str)`
давал ложь, и драйвер не читал ни одного ключа. `radio.uart` «срабатывал» только
потому, что его дефолт и так равен 1. (Тем же тихо страдал `assoc.*` у desktop —
он просто возвращал «нет обработчика».)

**Фикс:** таблица `k_cfg` (`get_str`/`get_int`/`get_bool` поверх
`ag_sysconfig()` + `ag_cfg_get*`; `set_str`/`commit` пока `-AG_ENOTSUP` — запись
в SYSTEM.CFG остаётся делом shell) и `.cfg = &k_cfg`. Это правка **прошивки**
(пересобрать и прошить образ esp32, не только `.SYS`). ABI-minor не менялся:
поле уже было в структуре, просто пустое.

После фикса — сквозной путь через ESP-07 подтверждён на плате:
```
net use atradio  → joining 'RT-...' → CWJAP OK → ip 192.168.0.126
net resolve example.com → 8.6.112.0
wget http://example.com/ → 200 OK, 559 bytes, saved A:\index.htm
```
DNS, TCP и HTTP работают через `net use atradio`. Пароли Wi-Fi живут только в
`C:\SYSTEM.CFG` на плате и в репозиторий не попадают.
