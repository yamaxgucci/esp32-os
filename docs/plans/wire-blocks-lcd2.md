# Блоки по проводу: пара S3-Zero ↔ Touch-LCD-2 (архив)

> Архив для сравнения. LCD-2 продана 23.09.2026; все замеры с ней — здесь, как были. Текущая пара и новая таблица — в [wire-blocks.md](wire-blocks.md).

S3-Zero (COM6) ↔ Touch-LCD-2 (COM9), те же четыре припаянных провода
(10 CS, 11 MOSI, 12 CLK, 13 MISO + земля; UART — на 11/13).
Прибор: `apps/wireblk` (`WIREBLK.AXE`), запуск: `tools/wireblk.py`.

**Как считается.** Блок = `WBLK` + номер (4 байта) + содержимое, вычисляемое
из номера; приёмник пересчитывает каждый байт. `sent` — сколько отправил
отправитель (его файл `c:\wireblk_tx.txt`), `good` — сколько целых принял
приёмник (`c:\wireblk.txt`), `bad` — принято повреждёнными, `lost` =
`sent − good`. КБ/с — байты целых блоков за время от первого до последнего
целого. `%max` — от предела линии: UART 8N1 = бод/10 байт/с, SPI = такт/8.

**Режимы.** `uart` — отправка через DMA UART (UHCI, перенесён из ветки
`worktree-fallout-cxx`), приём — FIFO и прерывания. `uartcpu` — без DMA.
`spi` — Zero всегда хозяин: Z→LCD идёт по MOSI, LCD→Z по MISO.
`load` — вычислительная нагрузка на оба ядра: `tx` у отправителя, `rx` у
приёмника, `both` у обоих.

### 16 Мбод, непрерывный приём через DMA

Своя задача порта держит смонтированным один из четырёх буферов по 4 КБ всё время: как только буфер полон (или линия замолчала — idle EOF), она сразу монтирует следующий свободный и только потом отдаёт полный читателю. Разбор блоков идёт в другом буфере. Разрыв без DMA — одно переключение задачи, против 80 мкс, которые держит FIFO.

Так что `lost` в строках DMA-приёма на 16 Мбод — смесь потерь на стыках и ошибок линии; ошибки линии — это столбец `bad`. Строки 4/8/10 Мбод этой пары (приём через FIFO) дефекта не касаются.
