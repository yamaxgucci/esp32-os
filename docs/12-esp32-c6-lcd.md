# Плата: Waveshare ESP32-C6-LCD-1.47

> Первая плата проекта не на Xtensa. Здесь — что она закрывает, что стоило
> портирование, и что проверять в каком порядке.
>
> Дата: 28 августа 2026.

## Что это за плата и зачем она нужна

**ESP32-C6-WROOM-1**: одно ядро RISC-V (RV32IMAC) на 160 МГц, 4 МБ flash,
512 КБ HP SRAM, 16 КБ LP SRAM, **PSRAM нет**. На плате: ST7789 172×320 (1.47″,
IPS), слот microSD, один WS2812, кнопки BOOT и RESET, разъём аккумулятора.
Радио — Wi-Fi 6 (802.11ax) и BLE 5; в первом образе включён только Wi-Fi.

**Разъём USB-C идёт прямо в чип.** Мостовой микросхемы на плате нет вообще:
GPIO 12 и 13 — это D− и D+ самого ESP32-C6. Отсюда всё остальное про консоль,
см. ниже.

Основная платформа проекта — **ESP32-S3 с PSRAM**, и это не меняется. Эта плата
нужна за тем, чего не закрывают ни эмулятор, ни CYD:

| Что | Почему только здесь |
|---|---|
| Другой набор инструкций | Слой портирования писался с обещанием, что смена архитектуры — это один файл. Здесь это обещание либо выполняется, либо нет |
| `.AXE` / `.SYS` под RISC-V | `mkaxe.py` умел `--arch riscv32` с самого начала, но ни один образ им не собирался. Теперь собирается — `ST7789.SYS` |
| Консоль не по UART | Единственная плата, где консоль — встроенное USB-устройство, а UART0 свободен и выведен на гребёнку |
| Одна шина SPI на панель и карту | На CYD они на разных хостах. Здесь SPI2 — единственный, и делить его приходится по-настоящему |
| USB на чипе | У ESP32 его нет, у S3 он занят другим. Здесь USB-стек чипа работает и это консоль |

Чего эта плата **не** закрывает: PSRAM (значит и спайк S-1), второе ядро,
профиль `full`, звук через ЦАП (у C6 их нет), **и восстановление после сбоя
приложения** — см. «Чего нет» ниже.

## Собрать и прошить

```
argon target esp32c6        переключить чип (полная пересборка)
argon build
argon flash -port COM5
argon target esp32s3        вернуться к основной платформе
```

**QEMU эту цель не запускает.** `argon run`, `argon test`, `argon nettest` —
только `esp32s3`. Перед коммитом надо переключиться обратно и прогнать
`argon check` там.

Что даёт сборка (измерено 28 августа 2026, `8e1192e-dirty`):

| | |
|---|---|
| образ | 1 334 608 Б из 1.9 МБ раздела (34% свободно) |
| HP SRAM | `.text` 127 КБ, `.bss` 116 КБ (из них 64 — арена кода), `.data` 16 КБ |
| куча после загрузки | **152 КБ** с картой и панелью (`display driver = panel`) |
| то же с системной поверхностью | 72 КБ (`driver = soft`, 160x86) — см. ниже |
| загрузка | 84 мс без драйвера панели, 562 мс с ним |

562 мс — это не медленный код, это datasheet: ST7789 требует 150 мс после
software reset, 120 после sleep out и ещё 120 при пробуждении, и они
складываются. Заливка чёрным поверх этого стоит ~40 мс на 40 МГц.

### Приложения

Образы `.AXE` / `.SYS` для этой платы собираются **другим компилятором**, и
это не настройка вкуса: `.AXE` носит набор инструкций в заголовке, и загрузчик
откажет чужому образу вместо того, чтобы его запустить.

```
argon apps --only ST7789.SYS
```

`build_apps.py` берёт пару (архитектура, компилятор) из `CONFIG_IDF_TARGET`
для всех записей, которые не назвали свою. `ST7789.SYS` называет —
`riscv32` / `riscv32-esp-elf-gcc` — потому что это единственный RISC-V образ в
дереве, где всё остальное Xtensa.

## `BOARD.CFG`

Лежит в [`boards/esp32-c6-lcd-1.47/BOARD.CFG`](../boards/esp32-c6-lcd-1.47/BOARD.CFG),
там же расписаны все пины и почему они такие. Залить:

```
python tools\boardtest.py -p COM5 --put "boards\esp32-c6-lcd-1.47\BOARD.CFG=c:\board.cfg"
```

Применяется на стадии `config`, то есть **со следующей загрузки**. `ver` тогда
печатает `esp32-c6-lcd-1.47` вместо `generic`.

| Что | Пины |
|---|---|
| SPI2 (общая) | sck 7, mosi 6, miso 5, 40 МГц |
| Панель ST7789 | cs 14, dc 15, rst 21, подсветка 22 |
| Карта microSD | cs 4, 20 МГц |
| USB (консоль) | 12 (D−), 13 (D+) |
| UART0 (свободен) | 16 (TX), 17 (RX) |
| WS2812 | 8 — он же strapping-пин |
| BOOT | 9 |
| flash внутри модуля | 24…30 (27 — питание) |

**miso идёт только к карте.** Панель read-only: прочитать её ID нельзя, и
драйвер не может проверить собственную работу — только писать и надеяться.

Панель и карта различаются **только chip select**. Порт держит по устройству
на каждый CS со своей частотой, так что ни драйвер панели, ни `sdspi` не знают
друг о друге; строчка `E spi: spi_bus_initialize(825): SPI bus already
initialized` при загрузке — это второй из них, и она ожидаема.

## Почему у этой платы нет системной поверхности

`[display] driver = panel`, а не `soft`, и это измерение, а не вкус:

| | `soft`, 160x86 | `panel` |
|---|---|---|
| свободно после загрузки | 72 КБ | **152 КБ** |
| приложение рисует в | 160x86, драйвер удваивает | **320x172, один к одному** |
| пунктов меню Marauder видно | 3 | **4** |

Восемьдесят килобайт, потому что мягкий путь — это не один буфер: передний,
задний и снимок, с которого восстанавливается консоль, по 27 КБ каждый. На
чипе, у которого вся куча 240 КБ, это треть — и потрачена она на то, чтобы
потом выбросить половину разрешения панели.

Чем платим: приложение, которое просит у ядра поверхность, не получает её
(`GFXDEMO`), и `gfxdump` нечего писать. Приложения, которые толкают свои полосы
через `gfx->present`, не замечают разницы — `gfxpix own`, `MARAUDER`,
эмуляторы. Консоль на стекле не зависит от этого вовсе: её рисует текстовый
путь самого драйвера ST7789.

## Драйвер панели

[`apps/st7789/st7789.c`](../apps/st7789/st7789.c), загружается сам:

```
drv install c:\st7789.sys
```

После этого он лежит в `/sys/drv/` и поднимается на каждой загрузке. Консоль —
**40×21** (320/8 на 172/8, четыре пикселя снизу ни в одну ячейку не влезают).
Framebuffer приложений — 160×86, кладётся на стекло ровно два к одному.

Написан с `apps/ili9341/ili9341.c` и следует ему близко намеренно: путь
консоли, отслеживание окна, масштабирование и правила «чего драйверу нельзя»
взяты оттуда, и переписать их своими словами значило бы завести второй набор
ошибок. Своё в нём — четыре вещи:

* **Смещение 34.** ST7789 адресует 240×320 что бы к нему ни было припаяно;
  панель 172 в ширину и стоит по центру. В ландшафте короткая ось — строки,
  поэтому смещение на Y. Ошибка здесь выглядит не как сдвиг, а как полоса шума
  сбоку.
* **Инверсия (`0x21`).** Панель normally-black IPS. Без инверсии каждый цвет
  выходит своим дополнением, и это читается как «подсветка загорелась над
  пустотой», а не как ошибка цвета.
* **Аппаратный сброс** на GPIO 21, которого у CYD не было. Стоит того: плата
  приезжает с заводской прошивкой, и та оставляет в регистрах панели много
  чего.
* **`MADCTL 0x60`** — ландшафт разъёмом USB вправо, проверено глазами. `0xA0`
  — то же самое для того, кто выводит кабель в другую сторону; смещение при
  этом не меняется, потому что 172 строки стоят по центру 240 (34 сверху,
  34 снизу).

## Что на ней проверено

| | |
|---|---|
| `.AXE` под RISC-V | грузятся, релоцируются, выходят чисто |
| графика | `gfxpix`: `acquired 160x86 stride=320`, `flushed in 53337 us` |
| | `gfxdemo`: `gfx 160x86 fmt=2 stride=320 db=1` |
| Wi-Fi | радио поднимается (`sta e4:b0:63:41:2c:4c`, 11ax coex), скан находит точки, стоит 39 КБ |
| MARAUDER | идёт на 320x172, меню ходится стрелками с консоли |
| SD | монтируется, `dir`, `recv`, `gfxdump` пишет |

53 мс на полный кадр — это 110 КБ по SPI на 40 МГц (22 мс чистой шины) плюс
масштабирование одним ядром на 160 МГц. Девятнадцать кадров в секунду на полную
перерисовку; полосами, как их шлёт `present`, платится только за изменившееся.

BLE не проверен, потому что его в образе нет.

## Сега: чего именно не хватает

`SMS.AXE` собирается под RISC-V без единой правки, и сразу отвечает цифрами:
код 80 752 Б, данные **914 380 Б**. Крупнейшие символы (этот компилятор, эта
плата):

| Символ | Байт | Пишется в работе? |
|---|---|---|
| `bp_lut` | 262 144 | нет — считается один раз |
| `SZHVC_add` + `SZHVC_sub` | 262 144 | нет |
| `bg_pattern_cache` | 131 072 | **да**, это кэш |
| `lut` + `mc_lookup` | 98 304 | нет |
| `ag_fm_tl_tab` | 26 624 | нет |

Около 650 КБ из них — таблицы, которые считаются при старте и дальше только
читаются. Соблазн очевиден: `mkaxe --rodata code` кладёт константы в кодовую
часть, а кодовая часть больше арены уезжает в `appfs` (1.5 МБ свободно) и
исполняется/читается оттуда XIP — то есть **не стоит ОЗУ вообще**. Останется
~260 КБ настоящих данных, из которых 128 — кэш тайлов, который сам режется
вчетверо.

И вот на чём это может умереть, и это надо померить раньше, чем переписывать
чужой GPL-код: **`bp_lut` читается по индексу из данных тайла**, то есть почти
случайно по 256 КБ, и то же самое делают таблицы флагов Z80 по операндам. Кэш
flash у этого чипа — десятки килобайт. Таблица в ОЗУ — это один такт; та же
таблица во flash с промахом — сотня. Если промах стоит столько, сколько кажется,
то перенос таблиц во flash обменивает «не помещается» на «не успевает», и вся
работа окажется впустую.

Поэтому первым шагом должен быть **не перенос, а замер**: маленький `.AXE`,
который читает 256 КБ константной таблицы из flash-XIP тем же случайным
шаблоном, что и эмулятор, и ту же таблицу из ОЗУ, и печатает наносекунды на
обращение. Одно число решает, стоит ли трогать SMS Plus GX.

## Чего нет

**Восстановления после сбоя приложения.** На загрузке плата говорит об этом
прямо:

```
W supervisor: faults will not be caught (-45): an application that faults
takes the system with it
```

Это не забытая работа, это цена архитектуры. Приём на Xtensa держится на
таблице обработчиков по причинам исключения, у которой в документации написано:
если обработчик вернулся, контекст потока восстанавливается **вместе с тем, что
обработчик в кадре поменял**. Именно это делает трюк законным — обработчик
двигает PC возврата и возвращается, а сбойная задача просыпается в процедуре
разбора на своём стеке.

У RISC-V в ESP-IDF такой таблицы нет: все исключения приходят в один вектор,
который зовёт `panic_from_exception()`, а тот не возвращается. Порт должен был
бы влезть впереди него и собрать ту же гарантию руками из `RvExcFrame`. Это
настоящая работа с настоящим способом ошибиться незаметно, и она не была тем,
что стоит между системой и этой платой. Контракт
[`argon/port/fault.h`](../components/argon_port/include/argon/port/fault.h)
такой ответ предусматривает словами: порт возвращает `-AG_ENOTSUP`, система
работает, `panic` печатает отчёт и перезагружает — как всякая другая прошивка
на этом чипе.

Также нет: **Bluetooth** (контроллер C6 — не контроллер ESP32, ни одного
`CONFIG_BTDM_*` из `sdkconfig.defaults.esp32` здесь не существует; добавлять
радио, которого ещё никто не просил, в первый образ — способ провалить
bring-up по причине, не имеющей отношения к плате), **звука** (ЦАП нет),
**АЦП** (включается, когда на плате появится что мерить), **HostFS**.

## Что пришлось починить, чтобы это стало возможно

Три из четырёх — общие поломки, которые просто не было на чём увидеть.

1. **`ARGON_ENABLE_NET` безусловно `select`-ил `ETH_USE_OPENETH`.** `select` в
   Kconfig нельзя отменить строкой в `sdkconfig.defaults`, так что QEMU-шный
   Ethernet компилировался и в радио-сборках тоже. На обеих Xtensa-платах это
   было невидимо — у обоих чипов есть настоящий EMAC, и `DR_REG_EMAC_BASE`
   поэтому существует. У C6 его нет, и сборка встаёт в чужом заголовке.
   Теперь `select ETH_USE_OPENETH if !ARGON_NET_WIFI`: линк — либо тот, либо
   этот.
2. **`espressif/esp_lcd_qemu_rgb` не собирается для RISC-V** (`soc/syscon_reg.h`
   не существует). Виртуальная панель теперь за `CONFIG_ARGON_PANEL_QEMU`,
   как камера за своим переключателем: при выключенном компонент даже не
   скачивается, а `panel_hw.c` честно отвечает «панели нет».
3. **`build_apps.py` перебивал компилятор записи компилятором цели.** Запись
   `ST7789.SYS` называет `riscv32`, и её всё равно отдавали Xtensa GCC, где
   она падала на `-mcmodel=medany`. Компилятор цели — для записей, которые
   своего не назвали.
4. **`ag_port_uart_config` отдавал ESP-IDF неинициализированный
   `uart_config_t`.** Годами. См. грабли 36.

## Грабли этой платы

* **PMP, а не кремний.** Главная. Вынесена в общий список — грабли 35.
* **Сброс по RTS роняет COM-порт.** USB-устройство — это тот же чип, который
  сбрасывают: Windows видит отключение, и открытый дескриптор становится
  недействительным. `boardtest.py` тогда падает с `ClearCommError failed`.
  Лечится повторным запуском; это не плата и не прошивка.
* **Три паники подряд уводят в recovery.** Штатное поведение, но на новой
  плате его встречаешь раньше, чем читаешь про него: модули и `AUTOEXEC` не
  грузятся, пока не сказать `boot normal` и не перезагрузиться.
* **Карта стоит 140 КБ.** 216 КБ свободных превращаются в 72, как только
  монтируется FAT (`allocation_unit_size` 16 КБ, восемь открытых файлов). На
  чипе с 512 КБ это первое, на что смотреть, если чего-то не хватает.
* **Пины SPI2 не те, что в IOMUX.** IOMUX хочет clock 6, MOSI 7 — плата
  развела наоборот. Всё идёт через GPIO-матрицу, и потолок поэтому 40 МГц, а
  не 80. Это факт о плате, а не то, что можно настроить.

## Что проверять, по порядку

```
argon target esp32c6
argon build
argon flash -port COM5

python tools\boardtest.py -p COM5 --seconds 8
    -> приглашение (1) C:\>   консоль по USB жива

python tools\boardtest.py -p COM5 --put "boards\esp32-c6-lcd-1.47\BOARD.CFG=c:\board.cfg"
python tools\boardtest.py -p COM5 ver io dev mem
    -> ver:  esp32-c6-lcd-1.47, configured by BOARD.CFG
    -> io:   sd cs 4 / miso 5 / mosi 6 / sck 7, usb 12-13, flash 24-30
    -> dev:  sd0 storage sdspi     карта смонтирована, приглашение A:\>

python tools\boardtest.py -p COM5 --put "build\apps\ST7789.SYS=c:\st7789.sys" "drv install c:\st7789.sys"
    -> ST7789: 320x172, 40x21 cells, backlight 22
    -> dev:  lcd0 display ST7789
```

Проверено 28 августа 2026: всё перечисленное — да.

## Что дальше

* **BLE.** Контроллер у C6 свой; `sdkconfig.defaults.esp32c6` придётся дать
  свой набор ключей, а не скопированный с ESP32.
* **Восстановление после сбоя на RISC-V** — см. «Чего нет». Один файл,
  `fault_hw.c`, и он уже разделён по архитектуре, так что писать надо только
  вторую половину.
* **WS2812 на GPIO 8** — RMT-периферия, драйвером `.SYS`.
* **Кнопка BOOT на GPIO 9** как вход: единственная кнопка на плате.
* **`argon boardnet`** — сетевые тесты по Wi-Fi здесь ещё не гонялись.
* **Framebuffer 320×172** (110 КБ) вместо 160×86 для приложения, которому
  нужен каждый пиксель и не нужно радио.
