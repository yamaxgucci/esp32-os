# Сеть — скачать, отдать, положить

Четыре команды: [`net`](#адрес), [`wget`](#скачать-файл), [`ftp`](#ftp),
[`httpd`](#отдать-каталог). Одинаково работают в QEMU (виртуальный Ethernet) и
на плате (Wi-Fi) — выше слоя портирования разницы нет, меняется только то, как
интерфейс поднимается.

Всё в открытом виде: **TLS в системе нет**, поэтому `https://` не скачивается, а
пароль FTP уходит по проводу как есть. Почему так — в
[10-network.md](../10-network.md); коротко: mbedTLS просит десятки килобайт на
буферы записей, а на этой плате с поднятым радио свободно около сорока.

## Адрес

```
C:\>net
address 10.0.2.15
```

Без адреса не работает ничего, и первый вопрос всегда этот. Если адреса нет,
команда так и говорит — интерфейс мог ещё не подняться, а DHCP мог не ответить.

**`net wait [секунды]`** — дождаться адреса (по умолчанию 30 с). Нужно в
скриптах: интерфейс поднимается задолго до того, как DHCP ответит, поэтому
`wget` в `AUTOEXEC.BAT` без этой строки промахнётся один раз и заработает, если
набрать руками.

```
C:\>net wait
address 10.0.2.15
```

**`net resolve <имя>`** — имя в адрес, тем же резолвером, которым пользуются
остальные команды:

```
C:\>net resolve example.com
example.com is 172.66.147.243
C:\>net resolve no-such-host.invalid
no-such-host.invalid: not found
```

На плате радио сначала подключают — `wifi scan`, `wifi connect #1 пароль`, и
сеть запоминается в `SYSTEM.CFG`, после чего поднимается сама при загрузке. См.
[09-esp32-cyd.md](../09-esp32-cyd.md).

## Скачать файл

```
C:\>wget http://10.0.2.2:8000/data.bin t:\data.bin
10.0.2.2:8000 ... connected
200 OK, 32768 bytes, application/octet-stream
32768 bytes in 0.1s (316 KB/s)
saved T:\data.bin
```

Имя файла можно не указывать — тогда берётся последний кусок URL, а каталог
текущий. Каталог вторым аргументом значит «туда, под именем из URL» — как у
`copy`.

```
C:\>t:
T:\>wget http://example.com/
example.com is 172.66.147.243
172.66.147.243:80 ... connected
200 OK, length unknown, text/html
559 bytes in 0.0s (272 KB/s)
saved T:\index.htm
```

Что оно умеет и чего от него ждать:

* **`http://` и `ftp://`**. `https://` отвечает `this system speaks http and ftp
  only` и не пытается сходить по 80-му порту: URL, который просили зашифровать,
  нельзя молча отправить в открытую;
* **перенаправления** — до четырёх, абсолютные и относительные. Каждое печатается,
  так что видно, куда в итоге ушли;
* **тело без длины и `chunked`** — оба случая; в файл попадает тело, а не
  обрамление. Файл, в котором пять процентов — заголовки блоков, не тот файл,
  который просили, и никто дальше этого не заметит;
* **`Ctrl+C`** прерывает; то, что успело приехать, остаётся файлом, и команда
  говорит, сколько там байт. Удалять чужие байты — не её решение;
* **файл открывается только после `200`**. Неудачная попытка не обрезает то, что
  лежало под этим именем раньше;
* **логина по HTTP нет.** Имя и пароль в `http://user:pass@host/...` не
  используются (Basic-авторизации здесь нет), и команда об этом говорит — иначе
  ответ `401` выглядел бы как неверный пароль;
* **код возврата** — 0 или 1, `errorlevel` после команды. `404` и «нет такого
  файла» отличимы от «сервер сломался», если это кому-то нужно в скрипте.

## FTP

```
T:\>ftp ftp://10.0.2.2:2121/
10.0.2.2:2121 ... connected
220-argon test server
220 ready
> USER anonymous
331 password, any password
> PASS ****
230 logged in
> TYPE I
200 fine
ftp: `help` for commands, `bye` to leave
ftp> ls
> PASV
227 Entering Passive Mode (192,168,100,50,249,230)
(server named 192.168.100.50; using the control address)
> LIST
150 here it comes
-rw-r--r-- 1 argon argon    32768 Jan  1 00:00 data.bin
-rw-r--r-- 1 argon argon       20 Jan  1 00:00 hello.txt
226 that was the listing
ftp> get hello.txt
> SIZE hello.txt
213 20
...
20 bytes in 0.0s
226 sent
ftp> bye
> QUIT
221 bye
```

Разговор печатается целиком — и то, что сказал сервер, и то, что послали мы
(`>`), кроме пароля. С FTP иначе нельзя: когда что-то не работает, дело почти
всегда на той стороне, и половина переписки не читается.

| Команда | Что делает |
|---|---|
| `ls [путь]` | список (`dir` — то же) |
| `cd <путь>`, `pwd` | каталог на сервере |
| `get <файл> [локальное имя]` | скачать в текущий каталог |
| `put <файл> [имя на сервере]` | отправить |
| `del <файл>`, `md <кат>`, `rd <кат>` | удалить, создать, убрать |
| `quote <текст>` | послать команду, которой здесь нет |
| `bye` | выйти (`quit`, `exit`, `Ctrl+C` — то же) |

* **Вход анонимный**, если не сказано иное: `ftp <хост> <пользователь> <пароль>`
  или `ftp://user:pass@host/каталог`. Хост можно писать с портом:
  `ftp 10.0.2.2:2121`. Пароль по умолчанию — адрес, как принято;
* **режим всегда двоичный.** Текстовый режим существует, чтобы переводить концы
  строк между системами, которые о них не договорились; здесь редактор читает
  оба вида, а испортить `.AXE` такой перевод может;
* **пассивный режим**, всегда. Плата за роутером не может принимать соединения, и
  `PORT` был бы функцией, которая работает на столе и больше нигде;
* **адрес из ответа `227` игнорируется** — данные идут на тот же адрес, с которым
  разговариваем, с портом от сервера. Строка `(server named …)` печатается
  именно тогда, когда сервер назвал что-то другое. Разбор — в
  [10-network.md](../10-network.md);
* один файл за раз, без `mget`. Несколько файлов — это цикл в `.bat` с `wget`.

Скачать один файл, не заходя в сессию:

```
T:\>wget ftp://10.0.2.2:2121/hello.txt
```

## Отдать каталог

```
T:\>httpd 8080 t:\
serving T:\ at http://10.0.2.15:8080/
Ctrl+C to stop
  /data.bin -> 200, 32768 bytes
  / -> 200
  /nothing.here -> 404
  /../board.cfg -> 403 (refused)
stopped
```

Без аргументов — порт 80 и текущий каталог. Каждый запрос печатается строкой:
что просили и чем ответили.

* **`GET` и `HEAD`**, остальное — `405`. Ничего не принимает: положить файл на
  плату можно через `ftp put` с другой стороны или `wget` изнутри;
* **каталог** отдаётся как `index.htm` / `index.html`, если он там есть, иначе
  списком со ссылками — по нему можно ходить браузером;
* **одно соединение за раз**, и соединение закрывается после ответа. Это не
  недоделка: при одном цикле `accept` открытое соединение — это клиент, который
  держит весь сервер, пока думает, а браузер держит их шесть;
* **из каталога не выйти.** `/../` и `/%2e%2e/` — оба `403`; путь сначала
  раскодируется, потом проверяется, и только потом приклеивается к корню;
* **`Ctrl+C`** останавливает. Это команда, а не служба: пока она работает,
  приглашения нет.

Из Windows при работе в QEMU сервер гостя виден на проброшенных портах
(`5558`…`5561`):

```
T:\>httpd 5558 t:\
```
```powershell
curl http://127.0.0.1:5558/data.bin -o data.bin
```

## Проверить, что всё это работает

На ПК поднимаются оба сервера, гость с ними разговаривает:

```powershell
argon nettest
```

Тридцать семь проверок: длина и её отсутствие, `chunked`, перенаправления,
`404`, `https`, FTP с двумя соединениями, и 32 КБ, которые гость сначала
скачивает, а потом отдаёт обратно — побайтово сравнивая с исходным файлом.
Серверы можно поднять и отдельно, чтобы потыкать руками:

```powershell
python tools/netfixture.py serve
```
