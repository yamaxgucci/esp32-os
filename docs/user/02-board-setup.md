# Как поднять ArgonOS на незнакомой плате

От «есть плата, ничего про неё не известно» до приглашения, карты памяти и
запущенного приложения. Расширение [03-board-config.md](../03-board-config.md),
где описан формат файлов настройки; здесь — порядок действий и что делать, когда
что-то не поднялось.

## 1. Подходит ли плата

| Требование | Почему |
|---|---|
| **ESP32-S3** | основная цель; на других чипах системы пока нет |
| **PSRAM**, лучше 8 МБ octal | данные приложений живут там; без PSRAM система загрузится, но приложение получит арену из internal SRAM и будет тесно |
| **flash 8 МБ или больше** | таблица разделов рассчитана на 8 МБ: 3 МБ на прошивку, 1 МБ на `C:`, остальное под будущий раздел кода |
| UART0, выведенный на разъём | консоль. USB-serial-JTAG станет вторым выходом позже |
| слот карты памяти | не обязателен: `C:` и `T:` есть всегда |

Модуль вида **N16R8** (16 МБ flash, 8 МБ octal PSRAM) — это то, на что настроены
значения по умолчанию. Плата с **quad** PSRAM требует
`CONFIG_SPIRAM_MODE_QUAD` вместо `CONFIG_SPIRAM_MODE_OCT`: с неверным режимом
PSRAM не определится вообще.

## 2. Прошить

```powershell
.\argon.cmd build
.\argon.cmd flash -port COM5
```

`flash` прошивает и сразу открывает монитор. Отдельно монитор —
`argon monitor -port COM5`; выйти из него `Ctrl+]`.

Консоль: **115200, 8N1**, без управления потоком. Терминал должен понимать
ANSI-последовательности — экран рисуется ими. Готовые варианты: монитор ESP-IDF,
PuTTY, любой VT100-совместимый. Классическая консоль Windows их не понимает, пока
не включён `ENABLE_VIRTUAL_TERMINAL_PROCESSING`; проверить свою —
`argon.cmd vt`.

## 3. Что должно появиться

```
ArgonOS 0.1.0 (081d35e-dirty)  esp32s3  profile=full
268 KB conventional memory, 8192 KB extended
ABI 0.2  cores=2  app core=1

boot: 98500 us, 3 subsystems not implemented yet ('boot' for details)

Type 'help' for a list of commands.
C:\>
```

Вторая строка — главная проверка железа. `extended` — это PSRAM: если там ноль, а
на плате она есть, дело в режиме (octal против quad) или в частоте. `conventional
memory` — internal SRAM, доступная ядру.

Строка про «3 subsystems not implemented yet» — норма для текущей версии, а не
поломка: этапов загрузки двенадцать, три из них (`memory`, `devices`, `modules`)
ещё не написаны, и система говорит об этом честно вместо того, чтобы делать вид,
что всё на месте.

Первым делом стоит спросить подробности:

```
C:\>boot
boot took 92888 us  (degraded)

  platform    ok           1619 us
  memory      not implemented yet
  log         ok            375 us
  board       ok             97 us
  console     ok          18429 us
  storage     ok          21473 us
  config      ok           7690 us
  devices     not implemented yet
  media       FAILED     err -5
  modules     not implemented yet
  supervisor  ok           2783 us
  shell       ok             21 us
```

`(degraded)` означает «что-то не так, как должно быть»: либо этап отказал, либо
он ещё не написан. Пока в системе есть ненаписанные этапы, это слово будет тут
всегда.

`media FAILED err -5` (`AG_EIO`) без вставленной карты — ожидаемо: карты нет,
монтировать нечего. Со вставленной картой это значит, что до неё не добрались, —
см. §5.

Два этапа критические: `platform` и `console`. Их отказ останавливает загрузку
насовсем — плата остаётся включённой, чтобы причину можно было прочитать с
консоли. Остальные отказы делают загрузку «ущербной», но приглашение появляется.

## 4. Первый запуск: что происходит само

* **`C:` форматируется автоматически**, если раздел пустой: терять там нечего, а
  система без места для настроек и журнала бесполезна. На пустом разделе первое
  форматирование занимает несколько секунд;
* **`T:` создаётся в памяти** всегда;
* **`A:` монтируется**, если карта нашлась и на ней есть файловая система. Сам
  ArgonOS съёмный носитель **никогда не форматирует**: неразмеченная карта — повод
  сообщить, а не стереть чужие данные.

Свежеотформатированный FAT на flash пишется заметно медленнее уже
использованного: первая большая передача после пересборки прошивки идёт минуты, а
не секунды, и выглядит как зависание. Это свойство FAT, а не отказ.

## 5. Карта памяти не определилась

Значения по умолчанию — раскладка слота 1 оригинального ESP32, которую скопировало
большинство более поздних плат:

| Вывод | Пин по умолчанию |
|---|---|
| `clk` | 14 |
| `cmd` | 15 |
| `d0` | 2 |
| `d1` `d2` `d3` | 4, 12, 13 |

Это отправная точка, а не факт о вашей плате. Порядок действий:

1. найти в схеме платы, куда разведён слот;
2. написать `C:\BOARD.CFG` с нужными пинами;
3. перезагрузиться и посмотреть `boot` и `log`.

```ini
; C:\BOARD.CFG
[board]
name = my-board

[sd]
interface = sdmmc
clk = 39
cmd = 38
d0  = 40
width = 1
```

**Почему файл именно на `C:`, а не на карте.** Пины, по которым система добирается
до карты, нельзя прочитать из файла, лежащего на этой карте. Поэтому всё, что
нужно для монтирования съёмного носителя, приходит из внутреннего flash.

**Как положить файл на `C:`, когда карты нет.** Через консоль, командой `recv`:
она принимает файл шестнадцатеричными строками и не требует ничего на другом
конце, кроме терминала. Файл маленький, набрать его можно и руками:

```
C:\> recv c:\board.cfg
send hex, END to finish
5b73645d 0a636c6b 3d33390a
END
12 bytes written
```

После этого `ver` покажет, какие файлы прочитаны:

```
configured by BOARD.CFG
```

Полезные ключи, когда карта всё равно не поднимается:

* `width = 1` вместо `4` — четырёхбитный режим требует, чтобы все четыре линии
  были разведены и подтянуты; однобитный работает на любой разводке, просто
  медленнее;
* `max_khz = 4000` — низкая частота на время выяснения; по умолчанию 20 МГц;
* `interface = spi` плюс `sck` `mosi` `miso` `cs` — если слот подключён по SPI;
* `interface = none` — сказать системе не трогать карту вообще;
* `card_detect` — пин детекта, если он есть.

Полный список ключей — [03-board-config.md](../03-board-config.md).

## 6. Новая карта

ArgonOS её не размечает. Либо форматированием на ПК (FAT32 или FAT16), либо на
самой плате:

```
A:\> format a:
WARNING: ALL DATA ON DRIVE A: WILL BE LOST!
Proceed with format (type YES)? YES
formatting drive A:...
format complete
```

Для скриптов — `format a: /y`, без вопроса. Форматировать можно **только `A:`**:
переформатировать диск, на котором живёт система, — способ потерять плату.

## 7. Проверить, что всё работает

```
C:\> ver          плата, чип, ABI — и какие файлы настройки прочитаны
C:\> mem          есть ли extended memory и сколько
C:\> mount        какие диски поднялись
C:\> dir a:       читается ли карта
C:\> fm           файловый менеджер: экран, клавиатура, оба диска сразу
C:\> log          что система сказала за время загрузки
```

`fm` — самая быстрая проверка того, что консоль, клавиатура и файловая система
работают вместе: он рисует полный экран, читает стрелки и F-клавиши и ходит по
дискам. Выход — `F10` или `Esc`.

Дальше — запустить приложение: [../sdk/01-getting-started.md](../sdk/01-getting-started.md).

## 8. Когда что-то не так

| Симптом | Куда смотреть |
|---|---|
| в консоли пусто | скорость 115200, тот ли порт, тот ли вывод UART0 на плате |
| в консоли мусор | скорость, либо терминал не понимает ANSI (`argon vt`) |
| `extended` — ноль | режим PSRAM (octal против quad), частота, модуль без PSRAM |
| загрузка останавливается насовсем | отказ `platform` или `console`; причина последней строкой в консоли |
| `media FAILED` с картой в слоте | пины в `BOARD.CFG`, `width = 1`, `max_khz` ниже |
| карта видна, но файлов нет | файловая система на карте: FAT32 или FAT16, не exFAT |
| приложение не запускается | `log` — там точная причина, и таблица отказов в [../sdk/01-getting-started.md](../sdk/01-getting-started.md#6-когда-не-запускается) |
| экран «съезжает» | размер окна терминала: экран рассчитан на 80×25 |

Ничего из этого не требует платы, чтобы попробовать заранее: система загружается
в QEMU (`argon run`), и все команды там те же.

## 9. Кириллица

Если установка русская, страницу стоит задать один раз в `C:\SYSTEM.CFG`, а не
набирать `chcp` после каждой загрузки:

```ini
[console]
codepage = 866
```

`866` — потому что она сохраняет символы рисования рамок на тех же местах, где
они в CP437: файловый менеджер и любые панели продолжают выглядеть панелями.
`1251` берут, когда надо читать файлы, пришедшие из Windows, — рамок в ней нет.
Терминал должен быть в UTF-8; система отдаёт ему UTF-8, переводя байты страницы
на выходе. Подробнее — [01-shell.md](01-shell.md).

## 10. Чего пока нельзя настроить

Пины реальной SPI/RGB-панели, автозапуск приложений. Soft display уже
настраивается секцией `[display]` (`driver` / `width` / `height`) —
см. [../03-board-config.md](../03-board-config.md). Шины I2C/SPI/UART и
`[modules]` (`device=`, `probe=`) тоже читаются. `[kernel]` (размеры арен) —
ещё план.
