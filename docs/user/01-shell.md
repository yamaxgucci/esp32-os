# Командная строка

Все команды с примерами, перенаправление вывода и диски. Приглашение выглядит
знакомо намеренно: кто работал в DOS, здесь уже умеет всё, что нужно.

```
Type 'help' for a list of commands.
C:\>
```

## Диски

Буквы диска — представление шелла; внутри система работает с POSIX-путями, и
принимает оба вида записи. `T:\apps\hello.axe`, `/tmp/apps/hello.axe` и
`t:/apps/hello.axe` — один и тот же файл.

| Диск | Точка монтирования | Что это |
|---|---|---|
| `A:` | `/sd` | карта памяти; появляется, только если карта вставлена и определилась |
| `C:` | `/sys` | внутренний flash (littlefs); форматируется автоматически при первом запуске; поиск имён без учёта регистра (`sms.axe` ≈ `SMS.AXE`), `cd` запоминает написание с диска. Нельзя создать `sega` рядом с `Sega` — будет «уже есть». Если раньше успели сделать оба каталога, лишний пустой уберите: `rmdir sega` |
| `T:` | `/tmp` | диск в памяти; исчезает при перезагрузке, зато быстрый |
| `D:` | `/dev` | устройства; каждое — «файл», см. [`dev`](#устройства) |

В QEMU папку Windows можно один раз упаковать на `A:`:
`argon run -Share D:\roms` — см. [03-host-share.md](03-host-share.md).

Шелл начинает работу на `A:`, если карта есть, иначе на `C:`, иначе на `T:` —
привычка загружаться с дискеты, если она в дисководе.

Смена диска — как в DOS, одной буквой:

```
C:\> t:
T:\>
```

Отдельного текущего каталога на каждом диске система **не помнит**: `A:` ведёт в
корень `A:`, а не туда, где вы были на нём в прошлый раз. После перезагрузки
именно этого и ждёшь.

Что где лежит:

```
C:\>mount
drive  mounted on   type        total        free  open
T:\    /tmp         ram       1024 KB     1024 KB     0
C:\    /sys         lfs       1024 KB     1016 KB     0
```

## Ввод

| Клавиши | Что делают |
|---|---|
| ← → Home End | перемещение по строке |
| ↑ ↓ | история, восемь последних команд |
| Backspace, Delete | удаление символа |
| `Ctrl+A` / `Ctrl+E` | в начало / в конец строки |
| `Ctrl+U` / `Ctrl+K` | стереть строку / до конца строки |
| `Ctrl+W` | стереть слово перед курсором |
| `Ctrl+C` | отменить набранное; во время работы программы — попросить её остановиться; во время долгой команды шелла (`type`, `copy`, `hexdump`, копирование в `fm`) — прервать её |
| `F12` | мягкая просьба остановиться (в QEMU `-Gfx` надёжнее, чем `Ctrl+C`, который часто съедает хост) |
| `Ctrl+\` | системный шелл `(sys) …>` (отдельно от 1…4); повтор в течение ~1 с — жёстко снять последнее user-приложение |
| `Alt+1`…`Alt+4` | пользовательский слот 1…4: пустой = свой шелл; с приложением = фокус app |
| `Alt+Tab` | цикл по слотам 1…4 (sys не входит) |
| `Ctrl+Alt+Del` | то же, что `Ctrl+\` (когда будет USB HID; из serial/терминала не послать) |

При старте ОС фокус на слоте 1: `(1) C:\>`. Системный шелл — только `Ctrl+\`,
промпт `(sys) C:\>`; там `run` и `fm` недоступны (только команды ОС).
При `-Gfx` клавиши ОС — в **терминале** `argon run`, не в SDL-окне видео.

Строка — до 256 символов, слов в команде — до 16. Tab нажимается, но ничего пока
не дополняет.

Аргумент с пробелом берётся в кавычки, и кавычки в аргумент не попадают:

```
C:\> type "c:\my notes.txt"
```

Регистр в именах команд и файлов не важен: `DIR`, `dir` и `Dir` — одно и то же.

## Перенаправление вывода

```
C:\> dir > files.txt        вывод в файл, файл создаётся заново
C:\> ver >> log.txt         дописать в конец
```

Работает для любой команды и действует на один вызов. Конвейеров (`|`) нет:
процессов, которые обменивались бы потоками, в системе пока не бывает.

## Команды

`help` печатает список; ниже — то, чего в одной строке не скажешь.

### Система

**`ver`** — версия, чип, плата, ABI:

```
C:\>ver
ArgonOS 0.1.0 (081d35e-dirty)
esp32s3 rev 0, 2 cores at 240 MHz, profile full
board generic, ABI 0.2, application core 1
```

Последняя строка появляется, если систему настраивали файлами: она перечисляет,
какие из них прочитаны. См. [02-board-setup.md](02-board-setup.md).

**`mem`** — память:

```
C:\>mem
                 total        free     largest
  internal       292 KB       252 KB       208 KB
  extended      8192 KB      8149 KB

  40 KB used by the system
  64 KB reserved for application code (free)
```

`internal` — быстрая память на кристалле, из неё живёт ядро и стеки; `extended` —
PSRAM, из неё живут данные приложений. `largest` — крупнейший непрерывный блок:
если он сильно меньше свободного, память фрагментирована. Последняя строка — арена
кода: она занята всегда, запущено приложение или нет, потому что резервируется на
линковке.

**`boot`** — сколько занял каждый этап загрузки и что не получилось. Первое, куда
смотреть, если карта не определилась или что-то не поднялось.

**`log [-n N] [clear]`** — системный журнал. После появления приглашения строки
из ядра и драйверов **не** печатаются на экран (чтобы не ломать строку ввода) —
они остаются только здесь. Во время загрузки echo ещё включён. Ошибки, отказы
и записи о падениях — смотреть через `log`.

**`power`** — частота процессора, экран и таймер простоя. Без аргументов —
состояние:

```
C:\>power
power: full, cpu 240 MHz (pinned 240), screen on
  steps: 240 160 80 MHz
  idle timer: off (`power auto on`)
  applications:
    pid 1   AMP          needs the full clock - 22 kHz tract
```

* **`power cruise`** — 160 МГц. Система берёт эту ступень **сама**, пока ни одно
  приложение не сказало, что ему нужна полная (`power cruise on|off` включает и
  выключает это, `power cruise declared` делает правило строгим).
* **`power eco [МГц]`** — прижать частоту (по умолчанию 80 МГц; допустимы только
  значения из `steps`).
* **`power doze [МГц]`** — то же и выключить экран.
* **`power full`** — обратно на максимум, экран включить. Никогда не отказывает и
  никого не снимает: это то, что набирают, когда что-то пошло не так.
* **`power screen off` / `on`** — только экран, режим не меняется.
* **`power auto on|off [сек_до_экрана] [сек_до_частоты]`** — таймер простоя.

**Ступень 160 стоит особняком.** Пока процессор питается от PLL, шина периферии
стоит на 80 МГц при любой из частот 240/160/80 — то есть падение до 160 меняет
только скорость счёта, и сломать может лишь то, что и так считало на пределе.
Поэтому там молчание считается согласием: не сказал, что нужна полная, — значит,
две трети хватит. В дереве девять образов, которым не хватает (`AMP`, `DX7`,
`SYNTH`, `GRAIN`, `IRFX`, `SMS`, `GB`, `CKTBENCH`, `GFXBENCH`), и каждый говорит
об этом первой строкой — тогда машина поднимает частоту сразу, как он запустился,
и опускает через несколько секунд после того, как он закончился.

**А вот `eco` и `doze` — не мягкая команда.** Это приказ:
система оповещает приложения, ждёт полсекунды, и **снимает те, которые не
ответили, что рассчитаны на новый режим**:

```
C:\>power doze
power: ended PWR (pid 1) - pretending to be realtime
power: doze, cpu 80 MHz (pinned 80), screen off
```

Так сделано намеренно: приложение, оставленное работать на третьей части своей
частоты, ломается тихо — щелчками в звуке, пропущенным дедлайном, пустым логом, —
а тихо оно ломаться не должно. Снятое приложение видно сразу и записано в `log`.

Не снимает никогда: `power full`, `power screen off`, `power cruise` (там
снимается только тот, кто прямо сказал, что не может), всё, что делает таймер
простоя, и приложение, которое ещё грузится.

**Таймер простоя** (`power auto`) — вежливый: он оповещает, но никого не снимает
и не понижает частоту, пока работает приложение, объявившее, что ему нужна полная
(экран при этом всё равно гаснет). Простой считается по вводу; любая клавиша
возвращает всё обратно. Он не отменяет то, что вы набрали руками: после
`power eco` таймер не вмешивается, пока не вернуть машину в покой командой
`power full`. Чтобы пережить `reboot` — `[power]` в `SYSTEM.CFG`
([03-board-config.md](../03-board-config.md)).

Если в сборке нет масштабирования частоты (`ARGON_ENABLE_PM`), режим всё равно
меняется — экран, оповещение, снятие — а команда пишет, что частота осталась на
месте. Подробности и цена — [`docs/11-power.md`](../11-power.md).

**`uptime`**, **`cls`**, **`echo <текст>`**, **`reboot`** — очевидны.

**`color <fg> <bg>`** — цвета текста, значения 0..15 в раскладке CGA
(0 чёрный, 7 светло-серый, 15 белый).

**`chcp [437|866|1251]`** — кодовая страница экрана. Без аргумента печатает
текущую и остальные:

```
C:\>chcp
active code page: 437  (CP437 - PC, box drawing, no Cyrillic)
  866  CP866 - MS-DOS Cyrillic
  1251  CP1251 - Windows Cyrillic, no box drawing
```

Ячейка экрана хранит **один байт**, как видеопамять PC, а кодовая страница
говорит, что этот байт значит. Отсюда всё остальное поведение:

```
C:\>chcp 866
active code page: 866
C:\>type c:\ru.txt
Привет, мир! Кодовая страница 866.
```

* **Смена страницы не переписывает то, что уже на экране** — она меняет смысл уже
  лежащих там байт, ровно как смена шрифта на PC. Тот же файл после `chcp 1251`
  выглядит как `ЏаЁўҐв, ¬Ёа!`, потому что байты те же, а страница другая;
* **`type` не угадывает кодировку файла.** Файл — это байты; страница решает, как
  их показать. Файл в CP866 читается при `chcp 866`, файл из Windows — при
  `chcp 1251`, файл в UTF-8 не читается ни при какой: в нём на букву два байта,
  а в ячейке — один;
* **`866` сохраняет рамки, `1251` — нет.** Символы рисования линий в CP866 стоят
  там же, где в CP437, поэтому файловый менеджер и любые панели переживают
  переключение на кириллицу. В CP1251 таких символов нет вообще, и рамка станет
  буквами;
* **набор с клавиатуры** переводится в байты той же страницы. Символ, которого в
  странице нет, не вводится вовсе: при `chcp 437` русская буква просто не
  появится в строке.

Чтобы не набирать `chcp` после каждой загрузки, страницу задают в `SYSTEM.CFG`:

```ini
[console]
codepage = 866
```

Терминал при этом должен быть в UTF-8 — система отдаёт ему именно UTF-8,
переводя байты страницы на выходе.

**`errorlevel`** — код возврата последней команды или программы. Ноль — успех.

### Файлы

**`dir [путь или шаблон]`**:

```
C:\>dir t:\demo

 Directory of T:\demo

note.txt                               17

       1 file(s)           17 bytes
       0 dir(s)       1048304 bytes free
```

Шаблон — `*` и `?`: `dir *.axe`, `dir t:\apps\h*.*`. Каталоги показаны как
`<DIR>`. Сортировки нет — записи идут в том порядке, в каком их отдаёт файловая
система.

**`cd [путь]`** — без аргумента печатает, где вы, а не уводит домой: так делал
DOS. `cd ..` на уровень выше.

**`type <файл>`** — вывести файл на экран. Для двоичного файла есть `hexdump`.

**`edit [файл]`** — полноэкранный текстовый редактор (встроен в ОС). Без имени
спросит его. Новый файл создаётся при первом сохранении.

```
C:\> edit t:\hello.c
```

Клавиши: стрелки / Home / End / PgUp / PgDn, Enter — новая строка, Tab —
четыре пробела, `F2` или `Ctrl+S` — сохранить, `Esc` или `F10` — выход
(с запросом, если есть несохранённые изменения), `F1` — справка. Файл не
больше 64 КБ и 2048 строк — тот же порядок, что арена приложений.

**`copy <откуда> <куда>`** — если приёмник каталог, файл копируется в него под тем
же именем. Копирования каталогов и шаблонов в приёмнике нет.

**`unzip <архив.zip> [куда]`** — без второго аргумента печатает содержимое архива
(имя, размер, метод); с каталогом назначения — распаковывает туда (store и
deflate). Создание архивов — отдельным `ZIP.AXE` на карте (`run zip.axe …`).

```
C:\> unzip a:\pack.zip
C:\> unzip a:\pack.zip t:\out\
```

**`del <файл или шаблон>`** — удаление. Шаблон работает; каталоги `del` не
трогает, для них `rd`. Подтверждения нет — `del *.*` сделает то, что сказано.

**`md <путь>`**, **`rd <путь>`** — создать и удалить каталог. Непустой каталог не
удаляется (`directory not empty`), рекурсивного удаления нет.

**`ren <старое> <новое>`** — переименование; второй аргумент может быть и просто
именем, и полным путём. Между дисками переименовать нельзя (`not permitted across
drives`) — это `copy` плюс `del`.

**`hexdump <файл>`** — шестнадцатеричный дамп с текстом справа:

```
00000000  41 58 45 31 00 00 02 00  01 00 b0 00 00 00 00 00  |AXE1............|
```

**`gfxdump [/live] <файл.ppm>`** — сохранить soft framebuffer (`fb0`) как
бинарный PPM (P6). По умолчанию пишет последний кадр после `ag_gfx_release`
(удобно сразу после `run` графического `.AXE`). `/live` — сначала нарисовать
текстовый экран на fb и сохранить его.

```
C:\> run t:\gfxdemo.axe
C:\> gfxdump t:\shot.ppm
wrote t:\shot.ppm
```

**`mount`** — список дисков (см. выше).

**`format <диск> [/y]`** — сделать новую файловую систему. Только `A:`:
переформатировать диск, на котором живёт система, — способ потерять плату, и
полезной причины для этого не нашлось. Без `/y` спрашивает подтверждение словом
`YES`.

**`recv <файл>`** — принять файл, набранный шестнадцатеричными строками в консоли:

```
C:\> recv t:\hello.axe
send hex, END to finish
41584531 00000200 ...
END
1040 bytes written
```

Как доставить программу на плату без картридера. Пробелы, табуляции и двоеточия
между байтами игнорируются, `END` на отдельной строке заканчивает приём.
Отправитель — любой скрипт, печатающий hex в порт; обвязка QEMU
(`tools/qemu-boot.ps1 -Put`) делает это и **сверяет число записанных байт с
размером файла**: байты в последовательной линии теряются молча.

### Программы

**`run [/b] <файл> [аргументы]`** — запустить приложение `.AXE` в **текущий
пользовательский слот** (1…4). Из `(sys)` команда отказывает — сначала Alt+N.
Без `/b` фокус переходит на приложение; с `/b` остаётесь в текущем слоте.

```
(1) C:\> run t:\spin.axe
started pid 1 in slot 1 (loading)
(1) C:\> slots
  slot  pid   prio     name
  sys   -     -        system
  1*    1     normal   SPIN
```

**`cc` (приложение `CC.AXE`)** — упрощённый C → `.AXE` прямо на ОС. Подмножество
и сборка: [`apps/cc/README.md`](../../apps/cc/README.md).

```
A:\> edit a:\hi.c
A:\> run a:\cc.axe a:\hi.c t:\hi.axe
A:\> run t:\hi.axe
A:\> errorlevel
```

**`ps`** — что загружено:

```
C:\>ps
  pid  name              state        memory
  1    SPIN              background    1040 KB
```

`memory` — это всё, что процесс занимает: его арена, стек и образ, а не то, что
он успел выделить. Приложение, ничего не выделявшее, всё равно занимает свою
арену целиком.

**`kill <pid>`** — снять процесс. Отказывается, если процесс держит системный
замок, и говорит об этом: отобрать мьютекс у снятой задачи FreeRTOS нельзя
законно, поэтому лучше отказ, чем сломанная система. Снятый процесс оставляет
запись в журнале и в `C:\crash.log` — с тем, сколько он прожил, сколько держал
памяти и сколько ресурсов за ним осталось.

**`slots`** — строка `sys` плюс слоты `1`…`4` (`*` = в фокусе). Пустой user-слот =
shell; иначе app (с колонкой приоритета). На `sys` приложения не садятся.

**`fg <slot|pid>`** — фокус на слот `1`…`4` или на слот процесса. В `sys` через
`fg` нельзя — только `Ctrl+\`. Пустой слот показывает `(N) …>`; слот с app
отдаёт ему клавиатуру.

**`prio <slot|pid> [low|normal|high]`** — показать или выставить приоритет
процесса. Приложения с аудио (`AG_AXE_NEEDS_AUDIO`) стартуют как `high`. Alt+N
приоритет не меняет: фоновый плеер может оставаться выше, чем copy в `fm`
(`prio 1 low` / `prio 2 high`).

`run` сажает приложение в **тот user-слот, где набрали команду** (не из
`(sys)`). Загрузка образа идёт на задаче процесса: шелл сразу свободен, можно
Alt+N на другой слот, пока в статусе ещё `loading`.

**`fm [левая] [правая]`** — файловый менеджер: две панели, `F1`..`F10`. Код в
прошивке, но запускается как **процесс в текущем user-слоте** (как `run`; из
`(sys)` отказывает). Аргументы —
каталоги панелей: `fm t: c:\sys`. `F3` — просмотр, `F4` — правка в `edit`
(встроенный; в `.AXE`-сборке ищет `EDIT.AXE`). Копирование (`F5`) — диалог со
шкалой; `Ctrl+C` отменяет между порциями (недописанный файл на приёмнике
убирается). Арена процесса ~256 KB (не 1 MB): иначе вместе с AMP часто не
хватает PSRAM.

Фоновые приложения **не пишут в текстовую консоль** чужого слота (`ag_printf`
без фокуса отбрасывается). Журнал (`log`) общий.

**Alt+1..4** сворачивает `fm` в фон: процесс жив, копирование **продолжается**,
отрисовки нет. Возврат на слот — тот же `fm`, не холодный restart. Повторный
`fm` в слоте, где он уже есть, только возвращает фокус.

Тот же менеджер на soft framebuffer — `GFXFM.AXE` (`apps/gfxfm/`,
QEMU: `argon run -Gfx`, затем `run gfxfm.axe …`).

Фоновые приложения **не рисуют** и не забирают клавиатуру; работа (copy, музыка)
по умолчанию идёт дальше.

### Сеть

Четыре команды, каждая с примерами — в [04-network.md](04-network.md):

| Команда | Что делает |
|---|---|
| `net` | адрес; `net wait [сек]` — дождаться DHCP (для скриптов); `net resolve <имя>` |
| `wget <url> [файл]` | скачать по `http://` или `ftp://`. `https://` — нет: TLS в системе нет |
| `ftp <хост> [юзер] [пароль]` | сессия: `ls`, `cd`, `get`, `put`, `md`, `rd`, `del`, `bye` |
| `httpd [порт] [каталог]` | отдавать каталог по HTTP, пока не нажат `Ctrl+C` |

```
C:\>wget http://10.0.2.2:8000/data.bin t:\data.bin
10.0.2.2:8000 ... connected
200 OK, 32768 bytes, application/octet-stream
32768 bytes in 0.1s (316 KB/s)
saved T:\data.bin
```

На плате радио сначала подключают (`wifi scan`, `wifi connect #1 пароль`; с
`/ap` — к названной точке доступа, а не к любой с этим именем) — оно
запоминается и поднимается само; в QEMU сеть появляется сама через DHCP, но не
сразу, поэтому `net wait` в скрипте перед первой выкачкой.

### Радио

Только на плате (QEMU радио не моделирует). Оба радио в одном образе,
поднимаются по одному; подробности и что чем проверено — [09-esp32-cyd.md](
../09-esp32-cyd.md). Каждая возможность за своим `CONFIG_ARGON_*` и включается по
необходимости.

| Команда | Что делает |
|---|---|
| `wifi [on\|off\|scan\|connect <#\|ssid> [пароль] [/ap]\|forget]` | станция: поднять радио, найти и присоединиться к сети |
| `wifi ap <ssid> [ключ] [/ch N] [/hidden]` / `wifi ap off` | своя точка доступа (192.168.4.1); `[ap]` в `SYSTEM.CFG` поднимает её при загрузке |
| `espnow [on\|off\|peer <mac> [ch] [key]\|send <mac\|bcast> <текст>\|listen [сек]]` | обмен датаграммами с другой платой без точки доступа |
| `mon [watch\|hop\|channel N\|filter\|tx <hex>\|deauth <bssid>\|beacon <ssid>]` | monitor-режим: слушать эфир и слать сырые 802.11 (по умолчанию выключен в сборке) |
| `bt [on\|off\|scan\|open <#\|addr>\|close\|forget]` | BLE-клавиатура: подключить клавиатуру/мышь как ввод консоли |
| `ble [scan\|connect <#\|addr>\|services\|read <h>\|write <h> <t>\|disconnect\|adv <name>\|midi [name]\|midi note <n>]` | общий BLE: смотреть эфир, подключаться к GATT, быть периферией и BLE-MIDI-устройством |

Приложение может быть BLE-MIDI-контроллером само — `MIDIPAD.AXE`, шесть
сенсорных кнопок (см. [09-esp32-cyd.md](../09-esp32-cyd.md)).

### Устройства

**`dev`** — что на этой плате есть:

```
A:\>dev
name      class     driver      size       flags
null      char      builtin     -
zero      char      builtin     -
con       char      builtin     -
flash0    storage   spiflash    1 MB       read-only
sd0       storage   sdmmc       64 MB      read-only removable
```

**`drv`** — загруженные модули `.SYS`. Без аргументов — список; `drv load
<file>` поднимает модуль сейчас; `drv install <file> [file …]` копирует на `C:\drv\`
(`/sys/drv/`, lowercase — LittleFS чувствителен к регистру), прописывает
`[modules] device=` в `C:\SYSTEM.CFG` и грузит (после reboot модуль
поднимается сам и снова публикует устройства в `dev`). Повторный
`install`/`load` с тем же именем в заголовке **заменяет** резидентный образ
(выгрузка + новый init) — файл на `C:` уже перезаписывался и раньше, но старый
код в RAM оставался. `drv uninstall <name>` снимает запись/файл; `drv unload
<name>` только выгружает из RAM (`name` — из заголовка, например `PCMVIRT`);
`drv probe` — I2C-подбор из `[modules] probe=`. `run` на `.SYS` отказывает:
это не приложение.

```
A:\> drv install a:\kbdvirt.sys a:\pcmvirt.sys a:\mousevirt.sys
installed c:\drv\kbdvirt.sys (loaded; autoload on boot)
installed c:\drv\pcmvirt.sys (loaded; autoload on boot)
installed c:\drv\mousevirt.sys (loaded; autoload on boot)
A:\> drv
name      version  code       data       path
PCMVIRT   1.0      ...        ...        /sys/drv/pcmvirt.sys
A:\> dev pcmvirt
A:\> drv uninstall PCMVIRT
uninstalled PCMVIRT
```

**`dev <имя>`** — про одно устройство подробно:

```
A:\>dev sd0
name    sd0
class   storage
driver  sdmmc
size    64 MB
open    0
flags   read-only removable
path    d:\sd0
sectors 131072 of 512 bytes
```

`open` — сколько дескрипторов на нём сейчас держат.

**Устройство — это файл на диске `D:`**, и работают обычные команды:

```
A:\>dir d:
A:\>hexdump d:\sd0            посмотреть, что реально лежит на карте
A:\>copy d:\con t:\notes.txt  набрать файл с клавиатуры, Ctrl+Z — конец
A:\>dir > d:\null             выбросить вывод
```

`d:\sd0` и `d:\flash0` — это **носитель посекторно, мимо файловой системы**: то,
что там на самом деле, а не то, что показывает `dir`. Оба только на чтение, и
намеренно: сверху смонтирована ФС со своим кэшем (`fat` на `A:`, `lfs` на `C:`),
и запись под ней испортила бы то, что она считает записанным.

Долгий вывод (`hexdump d:\sd0` — это 64 МБ, а `type d:\zero` не кончается
никогда) прерывается `Ctrl+C`.

### Пины и шины

**`io`** — карта пинов: что занято, кем и зачем. Свободные не перечисляются —
их сорок и они все одинаковые, — но их число видно:

```
A:\>io
 pin  state    owner  what         level
   2  system   system sd d0            0
   8  system   system i2c0             0
   9  system   system i2c0             0
  14  system   system sd clk           0
  26  system   system flash            0
  43  system   system console tx       0
  44  system   system console rx       0
30 of 49 pins free
```

`system` — пин, который нужен самой системе: консоль, карта, flash, PSRAM или
поднятая шина. Занять его нельзя, и это не вредность: пин 43 — это провод, по
которому вы читаете этот текст.

**`io <пин>`** — один пин. **`io <пин> in|up|down|out`** — настроить,
**`io <пин> 0|1`** — выставить уровень:

```
A:\>io 5 out
 pin  state    owner  what         level
   5  held     system gpio out         0
A:\>io 5 1
A:\>io 43 out
pin 43: access denied
```

Пин, занятый из шелла, остаётся занятым: шелл — такой же владелец, как
приложение, только он не завершается. Приложение своё отдаёт само, когда
кончается.

**`io i2c <шина>`** — что на шине. Классический скан, и первое, что стоит
сделать на незнакомой плате после того, как пины прописаны в `BOARD.CFG`:

```
A:\>io i2c 0
scanning i2c0...
  0x3c answers
  0x68 answers
2 device(s)
```

Если шина не описана, скан скажет об этом одной строкой, а не ста двенадцатью:

```
A:\>io i2c 1
scanning i2c1...
  i2c1: no such device
```

Пины шин задаются в `C:\BOARD.CFG` — см.
[03-board-config.md](../03-board-config.md). Шина поднимается при первом
обращении, поэтому её пины появляются в `io` только после того, как ею
воспользовались.

### PATH, AUTOEXEC, ассоциации

В `C:\SYSTEM.CFG`:

```ini
[shell]
path = a:\bin;c:\bin;h:\
autoexec = c:\autoexec.bat

[assoc]
.txt = edit
```

- Bare-имя (`hello`) ищет `hello.axe`, затем `hello.bat` / `hello.cmd` в cwd и
  по `shell.path` (`.axe` важнее `.bat`, если есть оба).
- `C:\AUTOEXEC.BAT` (или `shell.autoexec`) выполняется построчно после boot.
- Enter в `fm` на `.txt` открывает `edit`, если есть `[assoc]`; на `.bat`/`.cmd`
  запускает скрипт. `F4` всегда открывает текущий файл в `edit` (без `[assoc]`).

### Командные скрипты (`.bat` / `.cmd`)

Это **не** DOS batch: нет `IF`, `GOTO`, `%1`, переменных. Файл — список команд
шелла по одной на строку (пустые / `REM` / `;` / `#` пропускаются).

```
C:\> type a:\bin\setup.bat
echo preparing...
copy h:\app.axe c:\
drv install c:\pcmvirt.sys

C:\> setup
C:\> call a:\bin\setup.bat
```

Вложенность ограничена (защита от рекурсии). Аргументы скрипту пока
игнорируются.

Команда `boot` показывает стадии; `boot recovery` / `boot normal` — маркер
безопасной загрузки без модулей (см. [03-board-config.md](../03-board-config.md)).

### Чего в шелле нет

Полноценного batch-языка (`IF`/`GOTO`/`FOR`/`%VAR%`), переменных окружения
(`set`), конвейеров и циклов.

## Сообщения об ошибках

Неизвестная команда:

```
C:\> frobnicate
Bad command or file name: frobnicate
```

Файловые операции говорят словами: `file not found`, `is a directory`,
`not a directory`, `already exists`, `directory not empty`, `write protected`,
`insufficient disk space`, `drive not ready`, `access denied`,
`not permitted across drives`, `too many open files`, `invalid path`.

Отказы запуска перечислены в
[../sdk/01-getting-started.md](../sdk/01-getting-started.md#6-когда-не-запускается);
подробности каждого отказа — в `log`.
