# Прошить чужой чип самой платой (ESPFLASH / STM32FLASH)

> Плата ArgonOS сама прошивает подключённый по UART микроконтроллер, читая
> готовый `.bin` с диска. Отдельный USB-UART не нужен. ПК только *делает*
> бинарник (или его скачивают).
>
> Эта страница — рабочая инструкция, чтобы прошить модуль с нуля, в том числе
> из отдельной сессии/чата. Устройство и разбор — в
> [`docs/plans/ext-radio.md`](../plans/ext-radio.md).

Два инструмента, оба — загружаемые `.AXE` (в образ ядра ничего не добавляют):

| Чип | Инструмент | Протокол |
|---|---|---|
| ESP8266, ESP32, ESP32-S2/S3, ESP32-C3/C6/C2/H2 | `ESPFLASH.AXE` | ROM download (как esptool, без stub) |
| STM32 (F0/F1/F3/F4/L4/G0/G4…) | `STM32FLASH.AXE` | системный загрузчик, ST AN3155 |

Собрать оба: `argon apps --only ESPFLASH.AXE STM32FLASH.AXE`. Они уже копируются
в `build/apps/` и `build/sd_card/`.

## Общая идея

- Целевой чип вешается на **UART, который не консоль** (на платах ArgonOS консоль
  — UART0). По умолчанию инструменты берут **UART1**; пины UART1 задаются в
  `C:\BOARD.CFG` секцией `[uart1] tx=<пин> rx=<пин>`. **TX/RX крест**: TX платы →
  RX модуля, RX платы → TX модуля. Общая земля обязательна.
- Чтобы чип принял прошивку, его надо ввести в **режим загрузки** (см. ниже —
  у ESP и STM32 разные ноги и уровни). Это можно сделать **автоматически** ключом
  `-r`, если ноги загрузки/сброса разведены к GPIO платы, или **руками**.
- Бинарник кладётся на любую букву: A: (SD), C: (флеш), H: (папка хоста).

## ESP8266 / ESP32 — `ESPFLASH.AXE`

```
espflash id    [-c ЧИП] [-p ПОРТ] [-b БОД] [-r GPIO0 RST]
espflash write <файл> [-a АДРЕС] [-keep] [-c ЧИП] [-p ПОРТ] [-b БОД] [-r GPIO0 RST]
```

- `-c` — чип. По умолчанию `auto` (определяется по регистру опознания). Если не
  опознался — назвать явно: `esp8266 esp32 esp32s2 esp32s3 esp32c3 esp32c6
  esp32c2 esp32h2`.
- `-p` — номер UART (по умолчанию 1). `-b` — бод обоих концов (по умолчанию
  115200, держать одинаковым). `-a` — адрес во флеше (по умолчанию 0).
- `-keep` — не перезагружать модуль после записи, остаться в загрузчике. Нужно
  для **многосекционной** прошивки, которая пишется несколькими `write` (см.
  ниже). На всех, кроме последнего, ставь `-keep`; на последнем — не ставь, чтобы
  модуль стартовал прошивку.
- `-r GPIO0 RST` — авто-вход в download: ноги модуля GPIO0 и RST/EN, обе активны
  низким.

`id` не читает размер флеша (только чип и MAC). Размер нужен — прочитай его
`esptool flash_id` через мост (см. раздел про `uartbridge`).

**Режим загрузки:** GPIO0 = 0 в момент сброса. С ключом `-r` инструмент делает
это сам. Без ключа — вручную: перемычка **GPIO0 → GND**, затем **передёрнуть
питание** модуля, и только потом запускать команду.

Порядок:

```bash
run a:\espflash.axe id
run a:\espflash.axe write a:\firmware.bin
```

Сначала `id` — убедиться, что чип отвечает (печатает опознанный чип; для ESP8266
ещё слова MAC). Потом `write`. По окончании модуль стартует новую прошивку.

**Пример: залить заводской AT на ESP-01 (для драйвера `atradio`)** — положить
`AT.bin` на карту и `run a:\espflash.axe write a:\at.bin`.

### Многосекционная прошивка (несколько `.bin` по адресам) — `-keep`

Прошивка часто состоит из нескольких кусков по разным адресам (у ESP8266/ESP32 —
загрузчик, таблица разделов, приложение). Каждый кусок пишется своим `write`, и
между ними модуль должен **оставаться в загрузчике**: команда `FLASH_END`, которой
`write` завершает запись по умолчанию, закрывает сессию загрузчика ESP8266 (и её
ответ приходит криво), после чего следующий `write` не синхронизируется. Поэтому
на всех кусках, кроме последнего, ставь **`-keep`** (он не шлёт `FLASH_END`):

```bash
run c:\espflash.axe write c:\fw\boot.bin  -a 0x0     -keep
run c:\espflash.axe write c:\fw\part.bin  -a 0x8000  -keep
run c:\espflash.axe write c:\fw\app.bin   -a 0x10000 -keep
```

Про GPIO0: пока GPIO0 притянут к земле, модуль после сброса всё равно войдёт в
загрузчик, поэтому запуск прошивки после заливки — отдельный шаг: **снять GPIO0 с
земли (притянуть к 3.3 В) и передёрнуть питание**. Поэтому в примере выше `-keep`
и на последнем куске тоже — стартуем прошивку руками стрэпом, а не ребутом.

Так залит наш собственный RLINK-сопроцессор на ESP-07 (для драйвера `extradio`);
сборка прошивки и раскладка — в
[`firmware/esp8266-rlink/README.md`](../../firmware/esp8266-rlink/README.md).

## STM32 — `STM32FLASH.AXE`

```
stm32flash id    [-p ПОРТ] [-b БОД] [-r BOOT0 RST]
stm32flash write <файл> [-a АДРЕС] [-p ПОРТ] [-b БОД] [-r BOOT0 RST]
```

- Линия загрузчика STM32 — **8E1** (8 бит, чётность even, 1 стоп); инструмент
  открывает порт так сам. Бод по умолчанию 115200.
- `-a` — адрес (по умолчанию **0x08000000**, база флеша STM32).
- `-r BOOT0 RST` — авто-вход: BOOT0 **высокий** в момент сброса (обратный смысл к
  ESP). После записи с `-r` инструмент сам ставит BOOT0 низким и сбрасывает —
  чип запускает прошивку.

**Режим загрузки:** BOOT0 = 1 в момент сброса. Без `-r` — вручную: BOOT0 на
высокий, затем сброс (или питание), потом команда. Запустить прошивку после —
BOOT0 на низкий и снова сброс.

Порядок:

```bash
run a:\stm32flash.axe id
run a:\stm32flash.axe write a:\firmware.bin
```

`id` печатает product id (PID) чипа. `write` делает mass-erase (расширенный 0x44
или устаревший 0x43 — определяется автоматически) и пишет образ. Если флеш
защищён на чтение (RDP), стирание/запись откажут — RDP надо снять заранее.

## Если не отвечает

- **Бод** совпадает на обоих концах? Для STM32 порт именно **8E1**.
- **TX/RX не перепутаны и не забыт крест?** Земля соединена?
- Чип **действительно в режиме загрузки** (правильная нога, правильный уровень,
  и сброс/питание после установки ноги)?
- Пины UART1 заданы в `C:\BOARD.CFG`? Команда `io` в шелле показывает, какие пины
  порт занял.

## Прозрачный мост — прошивать чип с ПК через плату (`uartbridge`)

Иногда удобнее не встроенный флешер, а чтобы **обычный esptool/stm32-инструмент
на ПК** прошил чип, а плата была просто проводом (например, чип, которого наши
флешеры ещё не знают, или незнакомый протокол). Для этого есть команда ядра:

```
uartbridge <порт> [бод]
```

Она снимает UART0 (консоль) и соединяет его сырьём с указанным UART **до
перезагрузки**. Плата становится прозрачным USB-UART: байты идут
ПК → CH340 → UART0 платы → мост → UARTn → чип, и обратно.

**Консоль при этом умирает** — это нормально и единственный выход из моста —
**reset платы**.

Порядок (пример для ESP-01 на UART1 CYD, 115200):

1. В консоли платы: `uartbridge 1 115200`. После этой команды консоль — провод.
2. Ввести дальний чип в download-режим (для ESP — GPIO0→GND + питание; для STM32 —
   BOOT0 high + reset).
3. На ПК (COM платы, тот же CH340), `--no-stub` и тот же бод, что у моста:

   ```bash
   esptool --chip esp8266 -p COM7 -b 115200 --before no_reset --after no_reset --no-stub flash_id
   esptool --chip esp8266 -p COM7 -b 115200 --before no_reset --after no_reset --no-stub write_flash 0 firmware.bin
   ```

Три обязательных момента:

- **`--before no_reset --after no_reset`:** DTR/RTS-автосброс esptool дёргает ноги
  *самой платы* (так её и прошивают), а не дальнего чипа — иначе мост
  перезагрузится, и модуль надо вводить в download руками (см. п.2).
- **`--no-stub` и фиксированный бод (не поднимать `-b`):** мост копирует байты
  сырьём, а дальний UART зафиксирован на бод из `uartbridge <порт> <бод>`. Если
  esptool зальёт stub и поднимет бод на своём конце, UART модуля останется на
  старом — рассинхрон. Держи оба конца на одном боде.
- `flash_id` заодно **читает размер флеша** (`ESPFLASH.AXE id` этого не умеет) —
  по нему выбирается раскладка прошивки.

**Пример: залить заводской AT на ESP-07 (1 МБ) через мост.** Бинарники берутся из
`ESP8266_NONOS_SDK/bin` (512+512, «Nano AT», раскладка 8Mbit); модуль в download
(GPIO0→GND + питание):

```bash
esptool --chip esp8266 -p COM7 -b 115200 --before no_reset --after no_reset --no-stub \
  write_flash --flash_size 1MB --flash_mode dio --flash_freq 40m \
  0x00000 boot_v1.7.bin \
  0x01000 at/512+512/user1.1024.new.2.bin \
  0xfc000 esp_init_data_default_v08.bin \
  0x7e000 blank.bin  0xfe000 blank.bin
```

Закончив — снять GPIO0 с земли (на 3.3 В), reset платы (мост закроется, консоль
вернётся) и передёрнуть питание модуля; он стартует на AT, и `atradio` его видит.

Чем это отличается от `espflash`/`stm32flash`: там **плата** прошивальщик и читает
`.bin` с диска (консоль жива, ПК с esptool не нужен). Мост — наоборот: **ПК**
прошивает, плата лишь провод; зато работает с любым чипом и протоколом.

## Проверено на железе (2026-09-13)

Оба пути прошли сквозной тест на **ESP-07 + CYD**:

- **Плата шьёт сама** — `ESPFLASH.AXE`: залит наш RLINK-сопроцессор (загрузчик +

  (ESP8266EX, 1 МБ), залита штатная AT-прошивка, после чего `net use atradio` →
  Wi-Fi join → DNS → HTTP 200.

- `argon tests` — кодеки протоколов (`test_espldr`, `test_stm32ldr`, `test_rlink`):

- `argon apps --only ESPFLASH.AXE STM32FLASH.AXE` — сборка образов.
- `argon rlinktest` — RLINK end-to-end в QEMU против фейкового сопроцессора.
