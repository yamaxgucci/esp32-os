## Что это

**ArgonOS** — ОС для ESP32 с моделью исполнения в стиле MS-DOS: приложение
владеет машиной, ОС — тонкий слой сервисов. Не клон Linux, не «поделка»:
целевое применение промышленное. Обоснование всех решений — в
[00-architecture.md](00-architecture.md), план — в [04-roadmap.md](04-roadmap.md),
конфигурация плат — в [03-board-config.md](03-board-config.md), бюджеты и затыки
realtime-эмуляции — в [07-emulator-performance.md](07-emulator-performance.md).

Основная платформа **ESP32-S3** с PSRAM 8 или 16 МБ.
**Модуль с 32 МБ PSRAM непригоден** — см. «Грабли» ниже.

## Как работать

Одна точка входа, `argon.cmd` в корне. Это батник, а не `.ps1`, потому что
Windows по умолчанию запрещает выполнение скриптов PowerShell.

**Образы приложений и шара (обязательные пути):**

| Папка | Назначение |
|---|---|
| `build/apps/` | все собранные `.AXE` / `.SYS` (архив) |
| `build/sd_card/` | HostFS (`-HostFs`) и вход для `argon sync` / `-Share` |

`tools/mkaxe.py` после сборки сам копирует образ в обе папки (если не
`--no-stage`). Пиши `-o build/apps/NAME.AXE`. Подробнее —
[`docs/user/03-host-share.md`](user/03-host-share.md). Проверка звука
QEMU→Windows: [`apps/pcmvirt/README.md`](../apps/pcmvirt/README.md).

```
argon build              собрать прошивку
argon run                запустить в QEMU, консоль в этом окне (Ctrl+A, X — выход)
argon run -Sd            то же, с образом SD-карты
argon run -HostFs build\sd_card   живая папка Windows как H:
argon run -tcp           консоль на 127.0.0.1:5556, подключаться PuTTY в Raw
argon test ver mem       автотест: загрузка, набор команд, печать экрана
argon test -Sd ...       то же с картой
argon test -Put "build\apps\HELLO.AXE=t:\hello.axe" "run t:\hello.axe"
                         то же, предварительно залив файл в гостя через recv
argon test ... "~\x1c"   послать сырые байты, не дожидаясь приглашения:
                         так проверяется Ctrl+\ по работающему приложению
argon test -cp 866 ...   разобрать экран как CP866, а не CP437
argon tests              юнит-тесты на ПК (3480 проверок)
argon apps               собрать все .AXE / .SYS из `tools/apps.json`
argon apps --list        показать список, ничего не собирая
argon apps --only SYNTH.AXE DX7.AXE      собрать выборочно
argon apps --warnings    добавить -Wall -Wextra
argon check              локальный CI: `tests` + прошивка + `apps`
                         (то же в GitHub Actions: `.github/workflows/ci.yml`)
argon vt                 умеет ли эта консоль показывать экран
argon flash -port COM5   прошить настоящую плату
```

**Приложения собираются отдельно от прошивки, и это ловушка.** `.AXE` — своя
линковка, поэтому зелёная сборка прошивки про них не говорит ничего. Пока
команды сборки жили по одной строке в README каждого приложения, правка в
`apps/common` могла сломать полдюжины образов, а `argon check` этого не видел —
так и уехали в main четыре неработающих звуковых тракта (грабли 30). Теперь
список лежит в [`tools/apps.json`](../tools/apps.json), его собирает
`argon apps`, и он входит в `argon check` и в CI.

### Проверка виртуального звука (QEMU → Windows)

Полный чеклист также в [`apps/pcmvirt/README.md`](../apps/pcmvirt/README.md).
Образы уже должны лежать в `build/sd_card/` (`PCMVIRT.SYS`, `DX7.AXE`; демо
`build/sd_card/dx7/`).

В **PowerShell / Windows Terminal** из корня репо: `argon` не в PATH —
вызывай `.\argon.cmd`. Python — из IDF venv (не глобальный).

Сначала в каждом хост-терминале:

```powershell
cd "D:\Work\Unity Projects\ESP32-OS"
$py = "D:\Espressif\tools\python_env\idf5.5_py3.12_env\Scripts\python.exe"
```

1. Один раз (если нет `sounddevice`):
   `& $py -m pip install sounddevice`
2. Терминал 1 — гость:
   `.\argon.cmd run -Gfx -HostFs build\sd_card`
   Дождись сети (OpenEth / DHCP).
3. В госте (один раз на этот flash-образ):
   `drv install h:\pcmvirt.sys` → `dev pcmvirt`
   Должны появиться `pcmvirt` / драйвер `PCMVIRT`. После reboot `dev` без
   повторного install — ок.
4. Терминал 2 — хост (снова `$py=…` и `cd` в корень):
   `& $py tools\pcmplay.py`
   Можно `& $py tools\pcmplay.py --reconnect` или
   `& $py tools\pcmplay.py --record build\pcm_capture.wav`.
   Ждать клиента нормально: гость **не** блокируется.
5. В госте: `run h:\dx7.axe pcmvirt`
   Ожидай `sound = /dev/pcmvirt @ 22050 Hz`, без «waiting for host».
   Клавиши Z…M / Q…I или авто-MIDI из `h:\dx7\`.
6. Pass: в `pcmplay` строка `connected: 22050 Hz, 2 ch` и слышен звук;
   без плеера DX7 не ждёт; с `--reconnect` после обрыва звук возвращается.

Снять: `drv uninstall PCMVIRT`. Порт по умолчанию `127.0.0.1:5558`
(hostfwd у `.\argon.cmd run`).

Машинно-зависимые пути живут в `tools/local-env.ps1` (не в git):

| Что | Где |
|---|---|
| ESP-IDF 5.5.5 | `D:\Espressif\esp-idf` |
| Инструменты IDF (xtensa gcc, cmake, ninja, QEMU) | `D:\Espressif\tools` |
| Портируемый CPython 3.12 | `D:\dev\python312` |
| MinGW-w64 GCC 16.1 (host-тесты) | `D:\dev\mingw64` |

**Всё на `D:`** — на `C:` почти нет места.

### Чем и как проверяется

Железа нет. Проверка трёхуровневая, и это работает:

1. **Юнит-тесты на ПК** (`argon tests`) — всё, что не зависит от чипа:
   пути, конфиг, экран, кодеки терминала, редактор строки, VFS, RAM-диск,
   журнал, загрузчик, **DSP-слой `apps/common`** ([`host-tests/test_dsp.c`](../host-tests/test_dsp.c)).
   Собирается тем же GCC, что и целевой код, поэтому диагностика совпадает.
   Заголовки берутся из порта `bare` — то есть эта половина ядра компилируется
   при полном отсутствии машины под ней.
2. **Сборка всех приложений** (`argon apps`) — 26 образов `.AXE`/`.SYS` с
   `-Wall -Wextra`, ~30 с. Не тест, но ловит то, чего не ловит ни прошивка,
   ни юнит-тесты: приложение перестало компилироваться.
3. **QEMU** (`argon test`) — прошивка реально загружается. Эмулируется и
   SD-хост, и PSRAM. `build-host\vtdump.exe` восстанавливает экран из
   транскрипта, прогоняя его через наш же модуль экрана.
4. **Слушать** — `build-host\engine_smoke.exe` пишет `build/listen/*.wav`
   каждым звуковым движком, `build-host\synth_smoke.exe` — только `ag_synth`.
   Оба собираются вместе с host-тестами, чтобы не сгнить.
5. **Железо** — только спайк S-1 (исполнение из PSRAM) и латентности.

**Числа в звуке проверяются числами.** Слушать полезно, но четыре дефекта
подряд (пила со смещением, FM без боковых, ADSR в 256 раз быстрее, LFO вчетверо
быстрее) прошли мимо ушей и были найдены только измерением. Поэтому
`test_dsp.c` меряет размах и среднее осциллятора, частоту LFO, длительность
сегментов огибающей в миллисекундах и линейность свёртки — а не «звучит ли».

Загрузка в QEMU, измерено 16 августа 2026 (`argon test -Sd ver mem boot`):

| Стадия | С картой | Без карты |
|---|---|---|
| `devices` | 221 мс | 210 мс |
| `media` (SD + проба HostFS) | 160 мс | ~100 мс |
| `storage` | 43 мс | 120 мс |
| `console` | 19 мс | 21 мс |
| **всего** | **467 мс** | ~390 мс |

Цель <400 мс: почти. Разброс дают `storage` и `media`: свежеснятый образ flash
монтируется дольше уже использованного (грабли 18), так что сравнивать имеет
смысл этапы, а не общее число. Самая дорогая стадия — `devices`, и она пока не
разобрана по частям.

**Загрузка держалась на 3.4 с и никто не заметил** — стадия `media` ждала
хост-хелпера HostFS три секунды, а на плате его не бывает никогда. Разбор —
грабли 29.

Ядро занимает **70 КБ** internal SRAM (экран `mem`: «70 KB used by the
system»), прошивка **730 КБ** (`build/argonos.bin`). Что почём,
измерено сборками соседних коммитов на этой же машине:

| Что добавилось | internal SRAM | образ |
|---|---|---|
| было (процессы, консоль, ФС) | 41 КБ | 432 КБ |
| модель устройств | +1 КБ | +6 КБ |
| `io`: пины и шины | **+0 КБ** | +35 КБ |

Ноль во второй строке не опечатка: **при загрузке ни одна шина не поднимается**.
Драйверы I2C, SPI и LEDC стоят места во flash, но не занимают ни байта
оперативной памяти, пока ими не воспользуются, — и плата, у которой в
`BOARD.CFG` пины прописаны неверно, не начинает их дёргать до того, как
кто-нибудь посмотрит на консоль.

Память приложения (измерено в QEMU, `mem` и карта линковки):

| Что | Сколько | Где |
|---|---|---|
| код | потолок `CONFIG_ARGON_APP_ARENA_KB` (4..192, S3: 192); usable клипает `[memory] app_arena_kb=` | арена в D/IRAM |
| константы `.rodata` | вся свободная PSRAM; в арене только то, что помечено `AG_HOT_RODATA` | окно данных PSRAM |
| `.data` + `.bss` | вся свободная PSRAM, мегабайты | окно данных PSRAM |
| куча `ag_mem.alloc` | **арена процесса, 1 МБ** по умолчанию (`CONFIG_ARGON_APP_HEAP_KB`) или из манифеста | PSRAM |
| стек | 16 КБ по умолчанию, или из манифеста | internal SRAM, на время запуска |

Внутренней кучи после этого остаётся **258 КБ свободной** из 293 КБ.

Куча приложения — это его собственная арена, а не общая: при завершении процесса
она возвращается целиком одной операцией, и приложение не фрагментирует кучу
ядра. Проверено: `run t:\leak.axe` забирает 992 КБ и не отдаёт, второй запуск
находит ту же арену на месте.

## Что не работает и о чём нельзя забывать

1. **Модель процессов есть, но не вся.** Работает: до 4 процессов, своя задача,
   стек и арена, свой рабочий каталог, учёт и полный возврат ресурсов,
   `exec`/`spawn`/`wait`/`kill`, передний план и `fg`, `Ctrl-C` как просьба и
   `Ctrl+\` как снятие, crash-record в журнал, потоки и объекты синхронизации,
   перехват исключения с указанием смещения в коде приложения, per-process
   watchdog по заявке приложения (`ag_watchdog`), crash-record в
   `C:\CRASH.LOG` вместе с хвостом журнала.
   **Есть (session slots):** `Ctrl+\` → system shell (повтор → kill), `Alt+1..4` /
   `Alt+Tab`, `slots` / `fg`, `AG_EV_FOCUS_*` + `ag_focused()`, вывод
   несфокусированного приложения уходит в журнал, а не на общий экран
   (коммит `eed0743`).
   **Чего нет:** своего экрана на процесс — журнал это не заменяет.
   Дикий указатель по-прежнему может испортить чужую память — без MMU иначе не
   будет [Т-12]. Перехват спасает от типовых отказов (нулевой указатель,
   неинициализированный указатель на функцию), но не от порчи, которая уже
   случилась.
2. **Кода в приложении — не больше арены, 64 КБ.** Данные не ограничены ничем,
   кроме свободной PSRAM (проверено: 512 КБ bss), а вот код лежит в D/IRAM,
   потому что это единственная память, одновременно исполняемая и записываемая
   через один адрес, а ESP-IDF на S3 не отдаёт её в кучу. Мегабайты кода — это
   окно инструкций PSRAM, то есть спайк S-1, а ему нужна плата.
3. **Ячейка экрана — один байт, и это уже работает как надо** (`chcp`,
   `[console] codepage`): байт значит то, что говорит кодовая страница, а перевод
   в UTF-8 для терминала делает рендерер. Осталась мелочь: рамки в файловом
   менеджере всё ещё нарисованы `+-|`, хотя символы псевдографики теперь
   доезжают. Менеджеру для этого нужно спросить `ag_codepage()` и выбрать набор —
   в CP1251 псевдографики нет.
4. **Перерисовка всего экрана — ~90 мс, при движении курсора ~20 мс** (измерено
   менеджером, он это показывает). Неизменившиеся ячейки в терминал не уходят;
   время съедает ожидание консольного замка, который рендерер держит, пока
   передаёт кадр в UART. Лечится сборкой потока под замком и записью в порт
   после его отпускания — не сделано.
5. **`Ctrl+C` не доходит до гостя** в консольном режиме QEMU: он оставлен
   консоли, чтобы можно было выйти из зависшего эмулятора.
6. **Модель устройств, `.SYS` и I2C-`probe` есть; display class_ops — да.**
   Реестр, `/dev`, `ioctl`, пины, шины, `drv load`/`unload`/`probe` работают.
   Soft `fb0` отдаёт `ag_display_ops_t` через `dev->ops(h)` (ABI 0.23).
   Чего ещё нет: class_ops у остальных классов; probe по SPI-панелям; из шин —
   TWAI, 1-Wire, RMT, I2S, MCPWM.
7. **`io` проверено в QEMU, а не на железе, и это разные вещи.** Что проверено:
   отказ на пине системы, занятие и возврат пина, отзыв обработчика за упавшим
   процессом, чтение `BOARD.CFG`, подъём шины при первом обращении, скан I2C.
   Чего проверить нельзя: **уровень на пине** — QEMU не связывает выход со
   входом, так что `io 5 1` не меняет того, что читается, — и вообще любой
   обмен по шине, потому что на шинах эмулятора никого нет. Первое, что надо
   сделать с платой в руках: `io i2c 0` с настоящим датчиком.
8. **ADC выключен в стандартной сборке** (`CONFIG_ARGON_ENABLE_ADC`), потому
   что линковка драйвера ESP-IDF ломает загрузку в QEMU — грабли 26.
9. **Чтение `d:\con` держит замок файловой системы, пока оператор печатает.**
   `copy d:\con t:\notes.txt` ждёт строку, а ждёт он с замком VFS, поэтому
   фоновый процесс, читающий файл, ждёт вместе с ним. Причина общая: VFS
   держит свой замок на всё время обмена с бэкендом. Лечится тем же, чем
   медленная перерисовка экрана, — отпускать замок на время передачи.
10. **Нет сети, дисплея, USB.**
11. **В менеджере нет** копирования каталога целиком, рекурсивного удаления,
    поиска и командной строки внизу.
12. **Doom в QEMU: клавиатура не доезжает.** Несколько попыток (фокус SDL в
    `kbdvirt`, FIFO/bitmap в госте, мышь не в меню) не починили — с титра
    нельзя стартовать. Работа остановлена; план
    [`plans/doom-input.md`](plans/doom-input.md).

## Формат `.AXE` в трёх абзацах

Приложение линкуется на хосте **двумя непрерывными частями**: код с константами
и данные с bss. При переносе части по другому адресу **все PC-относительные
инструкции внутри неё остаются верными** — сдвигаются и инструкция, и цель.
Править надо только абсолютные 32-битные слова (литеральный пул, инициализированные
указатели). Поэтому в ядре нет ни ELF-парсера, ни декодера инструкций:
`tools/mkaxe.py` выдаёт список смещений, загрузчик копирует, прибавляет смещение
и прыгает.

Части переезжают независимо, поэтому у каждой релокации два признака: в какой
части лежит слово и в какую часть смотрит адрес внутри. Оба живут в младших двух
битах смещения — смещения выровнены на слово. Для RISC-V (`medany`, код достаёт
данные PC-относительно) образ собирается слитным: флаг `AG_AXE_CONTIGUOUS`
требует положить данные сразу за кодом и относить обе части одним смещением.

Собрать приложение и проверить его в эмуляторе:

```
python tools/mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc \
    --include sdk/include -o build\apps\HELLO.AXE apps/hello/hello.c
argon test -Put "build\apps\HELLO.AXE=t:\hello.axe" "run t:\hello.axe alpha"
```

Подпись `.AXE` (HMAC в `reserved[6]`, нули = без подписи):

```
python tools/signaxe.py build\apps\HELLO.AXE
python tools/signaxe.py --verify build\apps\HELLO.AXE
argon test -Put "build\apps\HELLO.AXE=t:\hello.axe" "run t:\hello.axe"
```

Soft graphics (без платы):

```
python tools/mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc \
    --include sdk/include -o build\GFXDEMO.AXE apps/gfxdemo/gfxdemo.c
argon test -Put "build\GFXDEMO.AXE=t:\gfxdemo.axe" \
    "run t:\gfxdemo.axe" "gfxdump t:\shot.ppm" "dir t:\shot.ppm"
```

Flash XIP / R-1 (код больше арены):

```
python tools\gen_bigcode.py
python tools\mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc \
    --include sdk/include -o build\BIGCODE.AXE \
    apps\bigcode\bigcode.c apps\bigcode\bigcode_body.c
argon test -Put "build\BIGCODE.AXE=t:\bigcode.axe" -TimeoutSec 180 \
    "run t:\bigcode.axe" "errorlevel"
```

Master System (отдельное GPL-приложение): точная команда сборки — в
[`apps/sms/README.md`](../apps/sms/README.md). Проверка:

```
argon test -Put "build\SMS.AXE=t:\sms.axe" -TimeoutSec 180 `
  "run t:\sms.axe 180" "errorlevel" "gfxdump t:\sms.ppm"
```

Звук (PSG + FM/`ag_fm` → mock / WAV, без I2S):

```
argon test -Sd -TimeoutSec 120 `
  "run a:\SMS.AXE 30 nolivepad mock" "errorlevel" `
  "run a:\SMS.AXE 60 nolivepad wav" "errorlevel"
```

Скорость (печатает fps, разбивку кадра и % realtime; `fps30` — показ через кадр):

```
argon test -Sd -TimeoutSec 240 `
  "run a:\SMS.AXE 600 nolivepad stats" "errorlevel" `
  "run a:\SMS.AXE 300 nolivepad fps30 stats" "errorlevel"
```

Mega Drive — то же самое, без ROM запускается синтетический картридж, который
крутит 68000 на месте (то есть меряется VDP при простаивающем процессоре):

```
argon test -Sd -TimeoutSec 240 "run a:\MD.AXE 300 nolivepad stats" "errorlevel"
```

Вручную доставить в эмулятор: `recv t:\hello.axe`, затем строки hex, затем `END`.

## Как запустить файловый менеджер и редактор

Оба **встроены в ОС** — команды шелла, доставлять ничего не нужно:

```
argon run
```

и в приглашении:

```
fm            обе панели в текущем каталоге
fm t: c:      левая на RAM-диске, правая на flash
edit t:\a.c   создать или открыть текстовый файл
```

В менеджере `F10` или `Esc` — выход, `F1` — клавиши. В редакторе `F2` —
сохранить, `Esc` / `F10` — выход, `F1` — справка.

Тот же код собирается и как обычное приложение `.AXE` — это способ проверить, что
встроенное и загруженное ходят через одну и ту же таблицу ABI, а не мимо неё:

```
python tools\mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc ^
    --include sdk/include --include apps/fm ^
    -o build\FM.AXE apps\fm\fm.c apps\fm\fmops.c apps\fm\fm_ui_text.c
argon test -Put 'build\FM.AXE=t:\fm.axe' 'run t:\fm.axe t: c:'
```

Графический twin (`GFXFM.AXE`, нужен `-Gfx`):

```
python tools\mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc ^
    --include sdk/include --include apps/fm ^
    --cflags "-Os -ffunction-sections -fdata-sections -DFM_GFX_BUILD" ^
    -o build\apps\GFXFM.AXE ^
    apps\gfxfm\gfxfm_app.c apps\gfxfm\fm_ui_gfx.c ^
    apps\fm\fm.c apps\fm\fmops.c
```

Проверять из скриптов удобно так — клавиши посылаются сырыми байтами с префиксом
`~`: `\x1b[B` это ↓, `\x1bOP` это F1, `\x0d` — Enter, `\x09` — Tab,
`\x1b[21~` — F10:

```
argon test 'fm t: c:' '~\x1b[B' '~\x1bOP'
```

**Одинарные кавычки в PowerShell не случайны:** аргумент, кончающийся на `\`,
в двойных кавычках съедает закрывающую кавычку, и следующие аргументы
склеиваются с ним. Проявляется как «клавиши не доходят до приложения».

## Слой портирования в двух абзацах

**Ядро не вызывает ESP-IDF.** Оно вызывает порт — 14 заголовков в
[`components/argon_port/include/argon/port/`](../components/argon_port/include/argon/port),
за которыми стоит реализация из `idf/` или `bare/`. Выбор — одна строка
`set(ARGON_PORT ...)` в `CMakeLists.txt` компонента. Проверяется это не на
слово: в `components/argon_kernel` нет ни одного включения `esp_*`,
`freertos/*`, `driver/*`, `soc/*` или `sdkconfig.h`, и `grep` по ним пуст.

Правило слоя — **он не имеет права стоить**. Всё, что отображается на нижний
вызов один к одному (память, время, задачи, примитивы синхронизации), —
`static inline` в заголовке порта, и кодогенерация в этих местах совпадает
байт в байт. Отдельными `.c` живёт только то, что действительно чужое:
`fault_hw.c` (таблица исключений Xtensa), `uart_hw.c`, `flash_hw.c`,
`storage_hw.c`, `io_hw.c`, `panel_hw.c`, `net_hw.c`. Само ядро при этом
**похудело на 6.0 КБ**, порт добавил 8.3 КБ, образ вырос на 2.4 КБ (+0.3%),
занятая internal SRAM не изменилась — 70 КБ. Что именно требуется снизу и в
каком порядке это писать для голого железа —
[`components/argon_port/bare/README.md`](../components/argon_port/bare/README.md);
там же честные оценки, из которых главная: планировщик — это не обёртка, а
ядро, и на нём стоит всё остальное.

Хост-тесты собираются против порта `bare`: у переносимой половины ядра под
ногами нет вообще никакой машины, и это ровно то, что должно быть.

## Устройства в двух абзацах

**Устройство — это файл на диске `D:`.** Реестр (`src/dev/device.c`) хранит имя,
класс, драйвер, флаги и владельца; `devfs` (`src/dev/devfs.c`) показывает его как
каталог, смонтированный в `/dev`. Из этого следует главное: таблица дескрипторов
одна на файлы и устройства, а значит учёт владельца и закрытие того, что осталось
от снятого процесса, уже написаны и не нужны второй раз. Положение принадлежит
дескриптору, поэтому `hexdump d:\sd0` читает карту посекторно, а два открытия
одного диска не мешают друг другу.

Подтаблица ABI `dev` добавляет к этому три вещи, которых у файла нет: открытие по
голому имени, перечисление с фильтром по классу (так приложение находит диск, не
зная, как его назвали) и `ioctl`. Что зарегистрировано сейчас: `null`, `zero`,
`con` (консоль как файл), `flash0` и `sd0` — оба только на чтение, потому что
сверху смонтирована FAT со своим кэшем.

```
argon run
```

и в приглашении:

```
dev                          что на этой плате есть
dev sd0                      про одно устройство, с геометрией
dir d:                       то же самое как каталог
hexdump d:\sd0               что реально лежит на карте, мимо файловой системы
copy d:\con t:\notes.txt     набрать файл с клавиатуры, Ctrl+Z — конец
dir > d:\null                выбросить вывод
```

## Пины и шины в двух абзацах

**Прямой доступ к железу разрешён, забирать чужое — нет.** Таблица пинов
(`src/dev/ioclaim.c`) знает про каждый пин, кто его держит и зачем. Пин системы
— консоль, карта, flash, PSRAM, а также пины поднятой шины — не отдаётся никому
и отвечает `-AG_EACCES`; пин, занятый другим процессом, — `-AG_EBUSY`; читать
можно любой. Всё, что процесс занял, возвращается при его завершении, вместе со
снятием обработчика прерывания: обработчик, переживший свой код, — это плата,
которая встанет на следующем фронте и не скажет почему.

Шины (`src/dev/io.c`) берут пины и скорости из `BOARD.CFG` и **поднимаются при
первом обращении**. Поэтому в памяти они не стоят ничего, пока не нужны, и
неверно описанная плата не начинает дёргать пины на старте. Номера — как в
даташите: `[i2c0]`, `[spi2]`, `[uart1]`.

```
io                           карта пинов: кто что держит
io 5 out                     настроить пин, io 5 1 — выставить
io i2c 0                     что на шине; первое, что делают с новой платой
```

То же самое из приложения, через таблицу ABI, — `apps/devs/devs.c`; он проверяет
себя сам, поэтому это ещё и тест того, что встроенное и загруженное ходят одной
дорогой:

```
python tools\mkaxe.py --arch xtensa --gcc xtensa-esp32s3-elf-gcc ^
    --include sdk/include -o build\DEVS.AXE apps\devs\devs.c
argon test -Sd -Put 'build\DEVS.AXE=t:\devs.axe' 'run t:\devs.axe' 'errorlevel'
```

## Грабли, которые уже стоили времени

Каждая из них проявлялась как что-то совсем другое.

1. **Окно внешней памяти S3 — 32 МБ, общее для flash и PSRAM.** При 32 МБ PSRAM
   `spi_flash_mmap` не находит адресов, и `esp_partition` **не видит ни одного
   раздела** — потому что читает таблицу через отображение. Выглядит как
   «сломана таблица разделов», хотя `esp_flash_read` по тому же адресу отдаёт
   корректные байты. Плата с 32 МБ PSRAM непригодна; QEMU запускается с 8 МБ.
2. **`src/con/` — зарезервированное имя устройства Windows.** Git молча
   пропускает такой каталог: заголовок закоммитился, `.c` — нет. Запрещены
   `con aux prn nul com1..9 lpt1..9`.
3. **`MALLOC_CAP_EXEC | MALLOC_CAP_8BIT` даёт ноль.** IDF помечает исполняемую
   память как только-словную — наследие оригинального ESP32.
4. **PowerShell может встать в середину вывода дочернего процесса.** Оператор
   вызова `& $qemu` заставляет PowerShell читать вывод как текст и печатать
   заново своим рендерингом, который не интерпретирует escape-последовательности
   — экран приходит стеной `←[2J` при правильно настроенной консоли. Нужен
   `Start-Process -NoNewWindow`.
5. **Классическая консоль Windows не интерпретирует ANSI**, пока не включить
   `ENABLE_VIRTUAL_TERMINAL_PROCESSING`, причём на handle, открытом как
   `CONOUT$` по имени — `GetStdHandle` не всегда консоль.
6. **TCP-порт QEMU без подключённого клиента выбрасывает вывод.** Нужен
   `wait=on`, иначе тест гоняется с эмулятором и иногда проигрывает.
7. **Логи через экран теряются при всплеске** — рендерер отправляет текущее
   состояние строки. Ради этого и сделан журнал.
8. **Длинные имена в FAT у ESP-IDF выключены по умолчанию.**
9. **Splatting массива в PowerShell передаёт аргументы позиционно** — `-Sd`
   приехал как значение `-Marker`. Нужен hashtable.
10. **`void**` на 64-битном хосте читает 8 байт** там, где в образе 32-битное
    слово. Образ — 32-битное адресное пространство независимо от машины.
11. **Секция в `.iram1` лежит в образе целиком.** Арена 64 КБ добавила ровно
    64 КБ нулей во flash и копирование их при старте, потому что имя секции не
    похоже на bss. Нужна `.iram.bss.*` — она `NOLOAD`, стоит только адресов.
12. **GCC уносит статический указатель, который нигде не пишется, в `.rodata`.**
    В фикстуре из-за этого не оказалось ни одной релокации в части данных, и
    проверять было нечего. Внешняя видимость (`g_`) лишает компилятор права так
    решать. С тех пор `.rodata` сама уехала в часть данных, так что такой
    указатель попадает туда же; внешняя видимость в фикстуре осталась — она
    проверяет именно *записываемое* слово.
13. **`-replace` со scriptblock в PowerShell 5.1 не вызывает блок**, а
    подставляет его исходный текст. Escape-последовательности в тесте
    превратились в мусор, и Ctrl+\ просто не доехал до гостя — выглядело как
    «супервизор не работает». Разбор `\xNN` теперь руками.
14. **Одна строка журнала — это несколько записей** (голова, тело, перевод
    строки). Без замка задача, вытесненная между ними, вклеивает свою строку в
    чужую; на одном ядре это было редко, с приложением на втором ядре стало бы
    обычным делом. В `log.c` теперь рекурсивный мьютекс.
15. **GCC удаляет разыменование литерального нуля целиком.** Тест «чтение по
    адресу 0» на `-Os` не проверял ничего: разыменование нуля — undefined
    behaviour, и компилятор вправе выбросить весь оператор, что и делает.
    Выглядело как «QEMU не моделирует отказ на чтении». Нужен указатель,
    про который компилятор не может доказать, что он нулевой (`volatile`).
16. **Удаление уже удалённой задачи FreeRTOS не сообщает ни о чём** — это
    повторное использование освобождённого TCB, и система просто перестаёт
    работать без единого сообщения. Так проявился упавший поток, который удалил
    себя, но остался в ресурсном списке помеченным как работающий. Любой путь
    завершения потока обязан сначала пометить запись.
17. **Консоль читала порт медленнее, чем идёт линия.** Один блок 64 байта за
    такт в 10 мс — это 6.4 КБ/с против 11.5 КБ/с на 115200. Всплеск переполнял
    буфер драйвера, и байты **терялись молча**: файл через `recv` приезжал тихо
    неверным. Теперь порт вычитывается до конца в пределах такта, и добавлен
    XON/XOFF — а обвязка сверяет число записанных байт с размером файла.
18. **Транскрипт QEMU — это отрендеренный экран, а не лог.** При прокрутке строки
    перерисовываются, поэтому считать в нём вхождения (например приглашения)
    можно только там, где «стало больше» — достаточный признак. Для «это точно
    произошло» нужен текст, который печатается один раз.
19. **Образ flash для QEMU нельзя проверять на свежесть по времени файла.**
    Эмулятор сам пишет в этот файл (в нём живёт littlefs на `C:`), поэтому после
    любого прогона образ выглядит новее прошивки, из которой собран, и тест
    молча гоняет предыдущую сборку. Час ушёл на «watchdog не работает», который
    работал. Теперь сверяется записанная метка (время и размер `argonos.bin`).
    Смена таблицы разделов / прошивки пересоздаёт образ и снова автоформатирует
    `C:`.
20. *(номер пропущен при правке 13 августа; оставлен, чтобы не сдвигать
    ссылки на грабли 21–28.)*
21. **Задачу, держащую мьютекс, нельзя снимать.** Легального способа отобрать
    мьютекс у удалённой задачи в FreeRTOS нет: удаление семафора с ожидающими —
    UB, пересоздание оставляет ждущих на старом хэндле. Поэтому супервизор
    сначала спрашивает `xSemaphoreGetMutexHolder`, ждёт до 500 мс и, если замок
    так и не отпущен, **отказывается** снимать процесс и говорит об этом.
22. **Обвязка QEMU писала транскрипт как текст, а не как байты.**
    `WriteAllText` без кодировки — это UTF-8, а транскрипт собирался посимвольно
    из байтов линии, поэтому каждый байт выше 0x7f уезжал в файл **двумя**. Пока
    гость говорил только ASCII, это было не видно; первая же строка кириллицы
    приехала как `Ð?Ñ€Ð¸Ð²ÐµÑ‚` — и выглядело это как ошибка в рендерере, а не в
    инструменте, которым его проверяют. Теперь Latin-1, то есть байт в байт.
    Та же ошибка в третий раз в этом проекте: **инструмент проверки надо
    проверять первым**, иначе он врёт про исправную систему.
23. **Таблицу переходов от `switch` GCC складывает в `.rodata`**, и в ней лежат
    абсолютные адреса, смотрящие в `.text`. Пока константы ехали вместе с кодом,
    это было слово в части кода, смотрящее в часть кода, — самый безобидный
    случай. После переезда `.rodata` в часть данных то же слово стало
    «в данных, смотрит в код», и такой комбинации в обычном приложении раньше
    не было ни одной. Формат её предусматривал, и загрузчик правит его верно, но
    проверялось это только специально написанным указателем на функцию; теперь
    такая таблица есть в фикстуре, и её ставит компилятор, а не автор теста.
24. **Управляющий код — это не символ, а нажатая клавиша.** Разбор ввода отдаёт
    `Ctrl+Z` как событие с `keycode = Z`, `mods = CTRL` и `unicode = 0` — и это
    правильно, потому что `Ctrl+Z` нечего писать в файл. Устройство `con`
    сначала читало `getch`, который отдаёт только символы, поэтому конца ввода
    оно не видело **никогда**: `copy d:\con t:\notes.txt` не заканчивалось, а
    следующие набранные команды уезжали в файл. Выглядело как «`copy` сломан».
    Всё, что ждёт управляющую клавишу, обязано читать события.
25. **Устройство, которое не кончается, вешает команду шелла.** `type d:\zero`
    читает до конца файла, а у потока конца нет, и `Ctrl+C` в шелле до этого
    никуда не смотрел: он отменяет набранную строку, а команда уже выполнялась.
    Машину оставалось только сбросить. Теперь `Ctrl+C`, нажатый когда на переднем
    плане никого нет, записывается супервизором, а `type`, `copy` и `hexdump`
    спрашивают об этом между порциями. Урок общий: новая возможность (устройство
    как файл) сделала законной ситуацию, которой у файлов не бывает.
26. **Линковка драйвера ADC из ESP-IDF ломает загрузку в QEMU.** Не вызов —
    **линковка**. `esp_adc` содержит конструктор `adc_hw_calibration()`, который
    выполняется до `app_main` и читает калибровочный автомат аналогового тракта;
    QEMU его не моделирует, и загрузка останавливается там, где последней
    строкой стоит предупреждение про efuse, до баннера ArgonOS. Искать при этом
    надо не в своём коде — в этой цепочке его нет вовсе. Поэтому ADC — опция
    сборки `CONFIG_ARGON_ENABLE_ADC`, по умолчанию выключенная, а `io->adc_read`
    без неё `NULL`. Общий урок: **компонент может стоить работоспособности,
    ничего не будучи вызванным.**
27. **«Владелец — ядро» недостаточно, когда ядро не одно.** Пины поднятой шины
    сначала занимались от имени `AG_PID_KERNEL` — и шелл, который тоже ядро,
    спокойно забирал у работающей шины её SDA командой `io 8 out`, потому что
    владелец совпадал. Ровно та драка, ради предотвращения которой таблица и
    заведена, только этажом выше, чем её ищут. Теперь шина **резервирует** пины,
    а резерв не отбирается ни у кого, включая ядро.
28. **Скан пустой шины писал в лог по строке на адрес.** Драйвер I2C из ESP-IDF
    считает таймаут ошибкой — и правильно, когда драйвер разговаривает с чипом,
    который должен быть на месте; но скан спрашивает про 112 адресов, и экран
    заполнялся сообщениями ESP-IDF, среди которых терялся собственный результат.
    На время скана тег `i2c.master` заглушается. И вторая половина той же
    ошибки: «на этом адресе никого» и «такой шины нет» сначала возвращали один
    код, так что скан несуществующей шины выглядел точно как скан пустой.
29. **Ограничение таймаута — это не починка зависания, а плата на каждой
    загрузке.** Проба HostFS могла не поймать хелпера с первого PING (QEMU
    переоткрывает TCP на UART1 после гостевого `reboot`), и цикл повторов
    ограничили тремя секундами. Ограничение сработало — и загрузка стала
    стоить **3.4 с вместо 0.4 с**, потому что «хелпер не отвечает» это не
    исключение, а норма: на плате его нет никогда. Цель проекта <400 мс при
    этом никто не перепроверил. Теперь на пути загрузки один короткий PING
    (100 мс), а ждут хелпера в фоновой задаче, которая монтирует `H:` когда он
    появится. Урок: **прежде чем ограничивать ожидание, спроси, кто платит за
    него в обычном случае.**
30. **Что не собирается автоматически — то и ломается.** Приложения
    линкуются отдельно от прошивки, их команды сборки лежали по одной строке в
    README каждого, и в CI не собиралось ни одно. На 3000 строк нового DSP не
    было ни одного теста. `argon check` был зелёным, пока в main лежали: пила
    с постоянной составляющей в полшкалы, FM-матрица без единой боковой
    полосы (модуляция прибавлялась к 32-битной фазе без сдвига — 0.000012
    цикла), ADSR, работавший в 256 раз быстрее задуманного, и LFO-треугольник
    вчетверо быстрее. Все четыре — арифметические, все четыре ловятся
    измерением за миллисекунду. Теперь есть `argon apps` и
    [`host-tests/test_dsp.c`](../host-tests/test_dsp.c), и оба входят в
    `argon check`.
31. **Свёртку нормируют по энергии, а не по пику.** IR-движок приводил все
    импульсные характеристики к одинаковому пиковому отсчёту — а усиление
    свёртки задаёт `sqrt(Σh²)`, и 500-мс хвост шума несёт в сотни раз больше
    энергии, чем 20-мс кабинет с тем же пиком. Выход упирался в потолок на
    каждом отсчёте, и wet-сигнал **перестал зависеть от входного уровня
    вообще** — вход тише в 16 раз, выход тот же. Вторая половина той же
    ошибки: спектры хранились в int16 с жёстким сдвигом `>>9`, который для
    одного IR переполняет корзины, а для другого оставляет в них единицы, так
    что свёртка превращалась в шум округления. Теперь IR нормируется по
    энергии, сдвиг выбирается по конкретному IR и снимается на выходе, а тест
    проверяет то единственное, что линейный фильтр обязан делать: вдвое тише
    на входе — вдвое тише на выходе.
32. **Генератор случайных чисел уровня файла делает результат
    невоспроизводимым.** `rnd16()` в `ag_ir.c` продолжал последовательность
    между вызовами, поэтому один и тот же пресет реверба строил каждый раз
    другую комнату: звук менялся под руками, а ни один рендер нельзя было
    повторить. Сеется при каждой загрузке пресета.

## Порядок дальнейших работ

Первые два пункта — по значимости, дальше по зависимостям.

1. **Модель процессов и супервизор — почти всё.** Сделано: процессы, арены, учёт
   ресурсов, `exec`/`spawn`/`wait`/`kill`, `Ctrl-C` и `Ctrl+\`, `ps`/`kill`/`fg`,
   подтаблицы ABI `proc` и `task`, перехват исключения, watchdog по заявке,
   crash-record в журнал и на диск. ✅ вывод несфокусированных процессов в
   журнал, ✅ `Alt+1..4` / `Alt+Tab`. Осталось по мелочи:
   * свой экран на процесс, а не общий на всех (разумно делать вместе с
     классом устройств `display`) — журнал это не заменяет.
2. ✅ **Документация для сторонних разработчиков** — написана, см. раздел
   [Документация для разработчиков](#документация-для-разработчиков), включая
   [`05-drivers.md`](sdk/05-drivers.md).
3. **Размер приложения — что осталось.** Данные и константы уже не ограничены
   ничем, кроме свободной PSRAM; ограничен код. Подробнее в
   [04-roadmap.md](04-roadmap.md):
   * ✅ **`.rodata` в часть данных** — шрифт 96 КБ стоит теперь 212 байт арены
     вместо 98 552, `AG_HOT_RODATA` оставляет отдельную таблицу в SRAM,
     `--rodata code` возвращает старое размещение целиком.
   * **Код в окно инструкций PSRAM** — мегабайты кода, спайк S-1, требует платы.
   * ✅ **`.text` в раздел flash и XIP** (R-1) — авто при переполнении арены;
     раздел `appfs`, `apps/bigcode` в QEMU.
4. ✅ **Кодовая страница экрана** — `chcp 437|866|1251`, `[console] codepage` в
   `SYSTEM.CFG`, `con->codepage`/`set_codepage` в ABI (0.3). Ячейка хранит один
   байт, конвертация на краях. Проверено в QEMU: файл в CP866 читается как
   кириллица, набранная кириллица доходит до `echo`, рамка из символов CP437 с
   кириллицей внутри рисуется приложением через `poke`, а после `chcp 1251` те же
   байты честно становятся другими буквами. Осталось: научить `fm` рисовать
   рамки псевдографикой, когда страница её содержит.
5. **Модель устройств, `io`, `.SYS` и I2C-probe — сделаны.** ✅ Реестр, `/dev`,
   `ioctl`, `dev`; ✅ пины и шины, `io`; ✅ загрузчик модулей, `drv`, стадия
   `modules`; ✅ `modules.probe` / `drv probe` / `ag_probe_hint` (ABI 0.7),
   примеры `apps/echo`, `apps/whoami`.
   Дальше, по зависимостям:
   * остальная периферия: TWAI(CAN), RS-485/Modbus, 1-Wire, RMT, I2S, MCPWM,
     и ADC, которому нужна не работа, а плата (грабли 26);
   * классы устройств со своими vtable (`class_ops`).

   Это же фундамент под **универсальную сборку с приёмом драйверов на месте** —
   фаза 4.5 в [04-roadmap.md](04-roadmap.md), добавлена 6 августа 2026.
6. **Дисплей и ввод**: ✅ soft framebuffer + `gfx` (ABI 0.9 draw) уже в QEMU без
   платы — `fb0`, front+back double-buffer, шрифт 8×16, текст→fb, `gfxdump`,
   `apps/gfxdemo`. Дальше на железо: драйверы ST7789/ILI9341/SSD1306 /
   RGB-панель, USB host HID (клавиатура), доводка `inp`. Это закрывает
   критерий v1.
   Сюда же добавился класс `audio` (I2S) — без него не будет ни звука, ни
   эмулятора.
7. ✅ **littlefs вместо FAT для `/sys`**
8. **Сеть**: Wi-Fi, сокеты, telnet-консоль как второй endpoint, подтаблица `net`.
   Тут же — приём драйверов и приложений по сети вместо UART.
9. **Спайк S-1 на железе**: исполнение из PSRAM, замер латентности, бенчмарки
   бюджетов из §10 архитектуры.
10. **Эмулятор Sega как `.AXE`** (фаза 3.5) — не развлечение, а проверка всей
    системы разом: код больше арены, полоса дисплея, звук, ввод, файлы. Master
    System реалистична в полную скорость; Mega Drive — только после S-1 и с
    честно названными компромиссами.

Написано после модели процессов, как и планировалось: подтаблицы `task` и `proc`
появились там же, и описывать ABI до них значило бы переписывать дважды.

**Чего документация стоила помимо текста** — два дефекта и один пробел, найденные
именно при попытке описать контракт словами:

1. `con->kbhit()` **забирал событие из очереди** и выбрасывал его, так что
   `if (kbhit()) c = getch();` — старейший идиом, какой есть, — терял клавишу и
   вставал на `getch`. Теперь есть `ag_console_peek_event`, который смотрит, не
   вынимая; проверено приложением, которое считает полученные символы.
2. `AG_APP` не давал задать **размер стека и арены**, хотя поля есть в формате
   образа и загрузчик их уважает. Добавлен `AG_APP_SIZED`; проверено: образ,
   попросивший 32 КБ стека и 2 МБ арены, получает ровно это.
3. `printf` ядра **обрезает вывод на 255 символах** (буфер форматирования один и
   на стеке). Не дефект, но то, о чём обязана сказать документация, иначе
   обрезанная строка выглядит как потеря вывода.
