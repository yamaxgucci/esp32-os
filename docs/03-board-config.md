# BOARD.CFG и SYSTEM.CFG

Оба файла лежат на внутреннем flash (диск `C:`) и читаются на стадии `config`.
Формат — привычный INI: секции в квадратных скобках, `КЛЮЧ=ЗНАЧЕНИЕ`,
комментарии с `;` или `#`. Значение в кавычках может содержать `;`.

```ini
; C:\BOARD.CFG
[board]
name = esp32-s3-devkitc

[sd]
interface = sdmmc
clk = 14
cmd = 15
d0  = 2
width = 1
```

Посмотреть, что применилось: команда `ver` печатает имя платы и список
прочитанных файлов.

## Почему именно внутренний flash

Порядок наложения настроек:

1. общие значения по умолчанию для чипа,
2. вкомпилированный board pack (выбирается по NVS, efuse или автодетекту),
3. `C:\BOARD.CFG`,
4. `C:\SYSTEM.CFG` — перекрывает предыдущее, потому что описывает конкретную
   установку, а не железо.

Чего в этом списке нет — `BOARD.CFG` на SD-карте. Пины, по которым система
добирается до карты, нельзя прочитать из файла на этой же карте. Поэтому всё,
что нужно для монтирования съёмного носителя, приходит из первых трёх
источников. Дисплеи, датчики и шины, обнаруживаемые позже, можно настраивать
откуда угодно.

## Ключи

### `[board]`

| Ключ | Значение | По умолчанию |
|---|---|---|
| `name` | имя платы, показывается в `ver` | `generic` |

### `[console]` — экран

| Ключ | Значение | По умолчанию |
|---|---|---|
| `codepage` | `437`, `866` или `1251` — что значит байт в ячейке экрана | `437` |

Применяется на стадии `config`, то есть после консоли: сообщения самой загрузки
всё равно ASCII. То же делает команда `chcp` — см.
[user/01-shell.md](user/01-shell.md).

### `[sd]` — карта памяти, диск `A:`

| Ключ | Значение | По умолчанию |
|---|---|---|
| `interface` | `sdmmc`, `spi` или `none` | `sdmmc` |
| `width` | 1 или 4 линии данных (только SDMMC) | `1` |
| `max_khz` | тактовая частота, кГц | `20000` |
| `clk` `cmd` `d0` `d1` `d2` `d3` | пины SDMMC | 14, 15, 2, 4, 12, 13 |
| `sck` `mosi` `miso` `cs` | пины SD-по-SPI | 12, 11, 13, 10 |
| `spi_host` | номер SPI-хоста (1 = SPI2) | `1` |
| `card_detect` | пин детекта карты, `-1` если нет | `-1` |

Значения по умолчанию — это раскладка слота 1 из оригинального ESP32, которую
скопировало большинство более поздних плат. Это отправная точка, а не факт о
конкретной плате: если карта не определяется, начинать надо отсюда.

`width = 4` требует, чтобы все четыре линии данных были разведены и подтянуты.
Если сомневаетесь — оставьте `1`: работает на любой разводке, просто медленнее.

`spi_host` — **номер SPI так, как его называет даташит**: `2` это SPI2, `3` это
SPI3. SPI1 занят flash-памятью и недоступен. (Внутри ESP-IDF нумерация другая,
со сдвигом на единицу; система переводит одно в другое сама, чтобы в файле и в
схеме стояло одно и то же число.)

### `[i2c0]`, `[i2c1]` — шины I2C

| Ключ | Значение | По умолчанию |
|---|---|---|
| `sda` `scl` | пины шины | **нет** |
| `khz` | тактовая частота, кГц (до 1000) | `100` |
| `pullups` | включить внутренние подтяжки | `yes` |

### `[spi2]`, `[spi3]` — шины SPI

| Ключ | Значение | По умолчанию |
|---|---|---|
| `sck` `mosi` `miso` | пины шины; `-1` если линии нет | **нет** |
| `khz` | тактовая частота, кГц (до 80000) | `1000` |

### `[uart1]`, `[uart2]` — последовательные порты

| Ключ | Значение | По умолчанию |
|---|---|---|
| `tx` `rx` | пины; `-1` если линии нет | **нет** |
| `baud` | скорость | `115200` |

`uart0` в этом списке нет намеренно: это консоль, то есть тот самый порт, по
которому система с вами разговаривает. Его пины зарезервированы, и попытка их
занять получает отказ.

### `[audio]` — подсказки для PCM (пины / rate)

Ядро всегда поднимает немое `/dev/pcmnull` и суммирующий `/dev/pcmmix`
(несколько приложений → один sink). Реальный вывод (virt → Windows, I2S на
плате) — загружаемые `.SYS` (`drv install`, см.
[`docs/sdk/05-drivers.md`](sdk/05-drivers.md) и [`apps/pcmvirt`](../apps/pcmvirt)).

| Ключ | Значение | По умолчанию |
|---|---|---|
| `driver` | зарезервировано для будущего I2S `.SYS` | `auto` |
| `bclk` `ws` `dout` | пины I2S Philips для будущего драйвера | нет (`-1`) |
| `mclk` | опциональный MCLK; `-1` если не нужен | `-1` |
| `rate` | частота по умолчанию для `pcmnull` / ioctl SETFMT | `22050` |

```ini
[audio]
rate = 22050
; пины — когда появится PCMI2S.SYS:
; bclk = 26
; ws   = 25
; dout = 22
```

`api->audio` — ярлык на `pcmnull` (discard). Приложения выбирают устройство
через путь: `pcmmix` / `/dev/pcmmix` для совместного выхода (сумма в
`pcmvirt` если он установлен, иначе `pcm0`/`pcmnull`); `pcmvirt` по-прежнему
exclusive для одного writer.

**У шин нет пинов по умолчанию, и это не недоделка.** Пин, на котором на одной
плате висит датчик, на другой может быть входом питания или линией дисплея.
Значение по умолчанию означало бы, что система начинает *выводить* на пин,
который никто не описывал. Неописанная шина отвечает `-AG_ENODEV` и называет
ключ, которого не хватает:

```
W (1364) io: i2c0 has no pins; set i2c0.sda and i2c0.scl in BOARD.CFG
```

**Шина поднимается при первом обращении**, а не при загрузке. Плата, которая
никогда не трогает I2C, не платит за него ни временем загрузки, ни памятью; а
плата, у которой в `BOARD.CFG` написаны неверные пины, не начинает их дёргать до
того, как кто-нибудь успеет посмотреть на консоль.

Пример для платы с датчиком на I2C и дисплеем на SPI:

```ini
[i2c0]
sda = 8
scl = 9
khz = 400

[spi2]
sck  = 12
mosi = 11
miso = 13
khz  = 40000
```

Что из этого применилось — покажет команда `io`: пины поднятой шины видны в
списке как занятые системой, с именем шины в колонке «what». Что на шине
есть — `io i2c 0`.

## Форматирование новой карты

ArgonOS **никогда** не форматирует съёмный носитель сам: неразмеченная карта —
это повод сообщить, а не повод стереть чужие данные. Новую карту готовят вручную:

```
A:\> format a:
WARNING: ALL DATA ON DRIVE A: WILL BE LOST!
Proceed with format (type YES)?
```

Для скриптов и автотестов есть `format a: /y`, пропускающий подтверждение.

Внутренний flash — противоположный случай: пустой раздел терять нечего, поэтому
он форматируется автоматически при первом запуске.

## `[display]`

```ini
[display]
driver = soft
width  = 320
height = 240
```

| Ключ | Значение |
|---|---|
| `driver` | `soft` (по умолчанию) — RGB565 в PSRAM, устройство `fb0`; `none` — без дисплея; имена панелей (`st7789` и т.п.) пока падают обратно на soft |
| `width` / `height` | размер soft framebuffer; 0 или отсутствие — 640×400 (80×25×8×16) |

Пины SPI-панели и тайминги RGB — когда появятся драйверы панелей.

## Память приложений

```ini
[memory]
app_arena_kb = 64
```

| Ключ | Значение |
|---|---|
| `app_arena_kb` | сколько килобайт из связанной арены кода (потолок `CONFIG_ARGON_APP_ARENA_KB`, на S3 обычно 192) реально отдаёт загрузчик. Clamp 4…потолок. Нет ключа — весь потолок. Хвост IRAM линкеру не возвращается. Нужен `reboot` после правки |

## Шелл: PATH, AUTOEXEC, ассоциации

```ini
[shell]
path = a:\bin;c:\bin;h:\
autoexec = c:\autoexec.bat

[assoc]
.txt = edit
.c = edit
.h = edit
```

| Ключ | Значение |
|---|---|
| `shell.path` | каталоги через `;` (DOS-пути). Bare-имя: `name.axe`, затем `name.bat` / `name.cmd` |
| `shell.autoexec` | скрипт после boot; нет ключа — `/sys/AUTOEXEC.BAT` при наличии файла |
| `assoc.<ext>` | обработчик: builtin `edit` или путь/имя `.AXE`. Enter в `fm` и «голый» файл в шелле |

`.bat` / `.cmd` — командные скрипты шелла (построчно, без `IF`/`GOTO`).  
`AUTOEXEC.BAT` — тот же формат. В recovery не выполняется.

## Энергосбережение: таймер простоя

```ini
[power]
cruise_mhz   = 160
cruise_s     = 5
cruise_when  = silence
auto         = 1
screen_off_s = 60
eco_s        = 300
eco_mhz      = 80
```

| Ключ | Значение |
|---|---|
| `power.cruise_mhz` | частота, на которой машина «катится», пока никому не нужна полная. По умолчанию 160 (единственная средняя ступень этих чипов); `0` — не катиться никогда |
| `power.cruise_s` | выдержка: сколько секунд после исчезновения последнего требовательного процесса до возврата на эту частоту. Гистерезис против мелькания |
| `power.crystal` | `1` — предлагать ступень 40 МГц (питание от кристалла). По умолчанию нет, и не из-за сомнений: на плате она работает — консоль невосприимчива (порты тактируются от REF_TICK / XTAL), SPI и I²C просто вдвое медленнее, радио перехватывается страховкой в обе стороны. Выключена потому, что **не измерено, что она даёт**: умолчание, меняющее вдвое медленную шину на неизвестную экономию, — решение, которого никто не принимал. Включать с амперметром |
| `power.cruise_when` | `silence` (по умолчанию) — катиться, пока никто не сказал, что ему нужна полная. `declared` — катиться только когда **все** запущенные объявили `FIT_ANY`; для установки, которая крутит чужие образы |
| `power.auto` | `1` — включить таймер простоя. По умолчанию **выключен**: машина, которая сама гасит себе экран через минуту, — приятный ноутбук и настораживающий прибор, и какой из двух эта, решает тот, кто её ставил |
| `power.screen_off_s` | секунд без ввода до выключения экрана; `0` — никогда |
| `power.eco_s` | секунд без ввода до понижения частоты; `0` — никогда. Обычно больше, чем `screen_off_s` |
| `power.eco_mhz` | частота для автоматического понижения; должна быть одной из тех, что печатает `power` (240/160/80). Нет ключа — 80, если эта плата её умеет |

Простой считается по вводу (клавиша, мышь, палец, кнопка пада), а не по выводу:
плата, которая печатает в никуда, — как раз тот случай, ради которого это и
нужно. Любой ввод возвращает всё обратно.

Ступень 160 МГц (`cruise`) — единственная, где молчание считается согласием: на
ней APB не двигается и ломаться нечему, кроме того, что и так на пределе. Спуск
до 80 (`eco`, `doze`) живёт по строгому правилу.

**Автомат никого не снимает** и никогда не понижает частоту до `eco`, пока живёт
приложение, объявившее `AG_POWER_FIT_FULL_ONLY` — экран при этом всё равно
гаснет. Команда `power eco`, в отличие от него, приказ: приложение, не
ответившее, что рассчитано на новый режим, снимается. Разбор —
[11-power.md](11-power.md), команда — [`user/01-shell.md`](user/01-shell.md).

Таймер можно включить и на ходу: `power auto on 60 300`. В `SYSTEM.CFG` — чтобы
пережить `reboot`.

## Safe boot / recovery

```ini
[boot]
recovery_after = 3
; safe = 1
```

| Ключ | Значение |
|---|---|
| `boot.recovery_after` | сколько unclean reset подряд → recovery (по умолчанию 3) |
| `boot.safe` | `1` — этот boot сразу в recovery |

Также маркер `C:\boot.safe` (`boot recovery` / `boot normal` в шелле). В recovery пропускаются `[modules]` и AUTOEXEC.

## Что ещё не читается из конфигурации

Секции `[modules]`, `[shell]`, `[assoc]`, `[boot]` уже читаются. Прочее — по мере появления. См. `docs/04-roadmap.md`.
