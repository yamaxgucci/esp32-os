# Устройство приложения

Что такое приложение ArgonOS изнутри: из чего состоит образ, где живёт его
память, чего у него нет и что оно обязано делать, чтобы вести себя как программа,
а не как захватчик машины.

Первый запуск — [01-getting-started.md](01-getting-started.md). Полный список
вызовов — [02-api-reference.md](02-api-reference.md).

## Три обязательные вещи

```c
#include <argon/argon.h>                 /* 1: обёртки над таблицей вызовов */

AG_APP("HELLO", "1.0", "you", 0);        /* 2: манифест образа */

int ag_main(int argc, char **argv)       /* 3: точка входа */
{
    return 0;
}
```

Больше ничего обязательного нет: ни стартового кода, ни инициализации, ни
регистрации. Загрузчик кладёт образ в память, вписывает адрес таблицы вызовов в
единственное слово внутри него и переходит на `ag_main`.

## Манифест

`AG_APP` разворачивается в структуру `ag_app_header_t` в секции `.ag_header` и в
слот `g_ag_api`. Из него система берёт то, что печатает `ps` и журнал, и то, что
проверяет загрузчик.

| Поле | Откуда | Зачем |
|---|---|---|
| `name` | 1-й аргумент, до 31 символа | имя процесса в `ps`, в журнале, в имени задачи FreeRTOS |
| `version` | 2-й, до 15 | справочно |
| `author` | 3-й, до 31 | справочно |
| `flags` | 4-й | см. ниже |
| `abi_major`/`abi_minor` | подставляются из заголовков | версия, против которой собрано |
| `stack_size`/`heap_size` | `AG_APP_SIZED` | размеры, если нужны свои |

Размеры по умолчанию нулевые, что означает «сколько даст система». Когда своего
размера мало или много:

```c
AG_APP_SIZED("DEEP", "1.0", "you", 0, 32 * 1024, 4 * 1024 * 1024);
/*                                    стек        арена            */
```

Разница между «по умолчанию» и «попросил» — в поведении при нехватке памяти:
запрошенный размер **обязателен**, и приложение получает отказ при запуске, если
его нет; размер по умолчанию система молча уменьшает, пока не влезет. Просить
стоит тогда, когда с меньшим приложение всё равно не заработает.

Флаги (`ag_axe_flags`): `AG_AXE_HOT_TEXT` — зарезервирован под разделение
горячего кода (IRAM) и холодного (XIP/PSRAM); пока весь код либо в арене,
либо целиком в flash XIP; `AG_AXE_NEEDS_GFX` — отказ без дисплея;
`AG_AXE_NEEDS_NET` — сети ещё нет; `AG_AXE_DRIVER` — `.SYS` (см.
[`05-drivers.md`](05-drivers.md)). `AG_AXE_RESIDENT` для TSR ещё не действует.
`AG_AXE_CONTIGUOUS` ставит сборщик (RISC-V); такие образы **не** уходят в
flash XIP — data должна быть рядом с code в writable памяти.

### Куда кладётся код

По умолчанию — арена D/IRAM (64 КБ). Если код (split-образ) больше свободного
места в арене, загрузчик включает **R-1**: релокация в scratch → запись в
раздел `appfs` → исполнение через mmap окна инструкций. В журнале это строка
`code … XIP at 0x42…`. Цена — запись во flash на каждый такой `run`.

Крупный пример нагрузки на цепочку «код + soft gfx + ввод»: `apps/sms/`
(Master System, GPLv2+ core). Образ не входит в прошивку.

## Вход и выход

`argc`/`argv` — как в C, и `argv[0]` — путь, которым приложение запустили: по
нему программа находит свои файлы. Аргументы **скопированы** в процесс, потому
что строки шелла лежат в его буфере строки, а фоновый процесс живёт дольше.
Предел — 16 слов и 256 байт на всё вместе; лишние слова отбрасываются, а текст,
который не влез, — отказ на запуске.

Возврат из `ag_main` завершает процесс, код возврата остаётся в `errorlevel`
шелла. `ag_exit(code)` делает то же самое из любого места, включая поток. Что
происходит дальше, приложение может не отслеживать: **все ресурсы возвращаются
системой** — память арены, потоки, мьютексы, семафоры, очереди, таймеры, открытые
файлы. Проверено: приложение, забравшее 992 КБ и не отдавшее, отдаёт всё при
завершении; второй запуск находит арену на месте.

Это не повод не убирать за собой. Приложение, закрывающее файлы само, работает
одинаково и когда его снимают, и когда оно завершается; полагающееся на уборку —
только во втором случае.

## Память

| Что | Куда попадает | Сколько |
|---|---|---|
| код, литералы, `.hot_rodata` | арена кода, internal SRAM | 64 КБ на **все** процессы (`CONFIG_ARGON_APP_ARENA_KB`, 4..192) |
| константы `.rodata` | окно данных PSRAM | вся свободная PSRAM |
| `.data`, `.bss` | окно данных PSRAM | вся свободная PSRAM |
| стек | internal SRAM | 16 КБ по умолчанию, 2..64 КБ из манифеста |
| `ag_malloc` | арена процесса в PSRAM | 1 МБ по умолчанию, или из манифеста |

Из этого следуют два практических правила.

**Массив в 512 КБ — нормально, функция в 100 КБ — нет.** Данные ограничены только
свободной PSRAM (проверено приложением с 512 КБ bss, свободно оставалось
7.6 МБ), а код — ареной, и её 64 КБ. Пока это так, большое приложение — это
приложение с большими *данными*.

**Константы кода не занимают.** Шрифт, картинка, таблица переводов едут вместе с
данными: проверено шрифтом 96 КБ, часть кода при этом 212 байт. Обратная сторона —
чтение из PSRAM вместо SRAM. Если таблица читается в горячем цикле и задержка
важнее места:

```c
AG_HOT_RODATA const uint8_t k_gamma[256] = { ... };   /* останется в SRAM */
```

Насколько велика разница, на QEMU не измерить — он не моделирует ни кэш, ни
латентность PSRAM. Пока нет замеров на плате, `AG_HOT_RODATA` стоит ставить по
необходимости, а не на всякий случай.

## Нет libc

Приложение линкуется с `-nostdlib`. Это не аскеза: реализация `printf` — это
20 КБ арены, которой всего 64.

Что взамен:

* **`ag_printf`, `ag_print`** — форматирование делает ядро, своих килобайтов не
  появляется. Поддержано то, что поддерживает newlib, включая `%p` и `%llu`;
* **`<argon/libc.h>`** — то, что компилятор подставляет сам (`memcpy`, `memmove`,
  `memset`, `memcmp`, `strlen`), объявлено слабыми символами: заголовок можно
  включить в каждый файл приложения без дублирующихся символов. Плюс строковые
  функции, ограниченные по построению: `ag_strlcpy`, `ag_strlcat`, `ag_strcmp`,
  `ag_stricmp` (сравнение имён на FAT — регистронезависимое),
  `ag_ends_with_i`, `ag_utoa` (число в столбик, без `printf`);
* **`ag_malloc`/`ag_free`** вместо `malloc`/`free`.

Чего нет и не появится само:

* `main` — точка входа называется `ag_main`;
* **конструкторов C++ и `__attribute__((constructor))`**: стартового кода нет,
  `.init_array` никто не обходит. Инициализировать — в `ag_main`;
* `errno` — код ошибки возвращается, а не откладывается в сторону;
* `atexit`, `signal`, `setjmp`-ловушек системных отказов;
* `stdio`, `stdlib`, `string.h` целиком — только то, что перечислено выше.

Вызов функции, которой в образе нет, — это отказ **сборки**, а не сюрприз на
плате: `mkaxe.py` не найдёт символ и скажет, какой именно.

## Потоки

```c
ag_thread_t t = ag_thread_create(worker, arg, "worker", 8 * 1024, 5, 0);
```

Это задачи FreeRTOS — вытесняющие, с приоритетами. Пределы, все про internal
SRAM: **4 потока на процесс**, стек 2..32 КБ (по умолчанию 8), приоритет 1..10
(выходящее за границы прижимается к ним). `flags` выбирает ядро:
`AG_THREAD_APP_CORE` (по умолчанию — то же ядро, что у приложения),
`AG_THREAD_SYS_CORE`, `AG_THREAD_ANY_CORE`.

Что стоит знать заранее:

* **поток, упавший на разыменовании нуля, роняет процесс целиком** — а не только
  себя. Так и задумано: продолжать работу с половиной потоков нельзя;
* **задачу, держащую мьютекс, система снять не может.** Отобрать мьютекс у
  удалённой задачи в FreeRTOS нельзя легально, поэтому супервизор ждёт до 500 мс
  и, если замок не отпущен, отказывается снимать процесс. Долгая работа под
  замком делает приложение неснимаемым;
* клавиатура принадлежит переднему плану, а не потоку: любой поток фонового
  процесса получит `-AG_EPERM` на попытке читать ввод.

## Работа с консолью

Консоль — виртуальный текстовый экран 80×25, который система отдаёт в UART, а
позже в telnet и на дисплей. Два разных способа с ним работать:

* **строками**: `ag_print`, `ag_printf`, `ag_getch`, `ag_readline` — как в
  терминале;
* **ячейками**: `ag_poke`, `ag_fill`, `ag_gotoxy`, `ag_color` — как в
  видеопамяти DOS. Это то, чем рисуются рамки и панели, и именно этим `ag_poke`
  отличается от `printf` в правый нижний угол: `poke` не прокручивает экран.

Клавиши без символа (стрелки, F1..F12) через `ag_getch` не приходят — для них
`ag_poll_event` из подтаблицы `inp`, отдающий целое событие с HID-кодом,
модификаторами и символом, если он есть. Полноэкранный пример —
[`apps/fm`](../../apps/fm/fm.c).

**Ячейка хранит один байт, и его смысл задаёт кодовая страница.** `ag_getch`
отдаёт байт этой страницы, а не код Unicode; `ag_poke` принимает его же. Для
всего, что сложнее ASCII, страницу надо спросить — байт русской буквы в CP866 и
CP1251 разный, а в CP437 её нет вовсе:

```c
ag_printf("code page: %u\n", (unsigned)ag_codepage());   /* 437, 866 или 1251 */
```

Рамки рисуются байтами CP437 (`0xda`, `0xc4`, `0xbf`, `0xb3`, ...), и в CP866 они
стоят там же — панель переживает переключение на кириллицу. В CP1251 их нет.
Перевод в UTF-8 для терминала делает система: приложение считает столбцы в
ячейках и про UTF-8 не знает.

Проверять ввод, не забирая его, можно `ag_kbhit()` — она смотрит, не вынимая, так
что `if (ag_kbhit()) c = ag_getch();` не теряет клавишу.

## Как быть хорошим процессом

Три вещи, каждая — одна строка кода, и все три про то, что систему с
приложением делят другие.

**Слушать просьбу остановиться.** `Ctrl+C` доходит до приложения как признак, а
не как убийство:

```c
while (work_left()) {
    if (ag_interrupted()) {        /* читается один раз и сбрасывается */
        tidy_up();
        return 1;
    }
    do_a_piece();
}
```

Приложение, которое проверяет, можно попросить; которое не проверяет — только
снять через `Ctrl+\`, потеряв то, что было в процессе.

**Заявлять watchdog, если можешь его выдержать.**

```c
ag_watchdog(500);                 /* «буду отзываться не реже 500 мс» */
for (;;) {
    ag_heartbeat();
    do_a_piece();
}
```

Только по заявке, и это принципиально: срок, назначенный системой, был бы неверен
для любого приложения, которое законно ждёт долго — карту, ответ, нажатие. `0`
снимает заявку; снимать её нужно перед долгим ожиданием.

**Не занимать передний план молча.** Фоновому процессу ввод не принадлежит:
`ag_getch` вернёт `-AG_EPERM`, а не будет ждать вечно. Приложение, которому нужен
ввод, должно либо быть на переднем плане, либо уметь работать без него.

## Падение

Приложение, разыменовавшее ноль, не роняет систему. Исключение перехватывается,
процесс снимается, а в журнал попадает запись с адресом отказа **и смещением
внутри собственного кода приложения**:

```
CRASH (pid 1) killed at 3128 ms uptime: faulted
  LoadProhibited at pc 40387234, address 00000000, sp 3fca1b20
  pc is offset 0x134 in its own code
```

Смещение — то, что нужно: по нему находится строка в дизассемблере
(`--keep-elf` у `mkaxe.py`, затем `objdump -d`), потому что образ на плате
переехал, а смещения в нём те же. Та же запись дописывается в `C:\crash.log`,
чтобы дожить до следующей загрузки; файл обрезается, когда перерастает 32 КБ.

Чего перехват не даёт: продолжить с места отказа, поймать отказ внутри
приложения, узнать значения регистров сверх напечатанных. И, поскольку MMU не
используется, дикий указатель может испортить чужую память **до** того, как
что-нибудь упадёт. Это плата за модель, а не недоделка.

## Несколько файлов и один исходник на две сборки

Файлов на входе `mkaxe.py` может быть сколько угодно; `AG_APP` — ровно в одном.
`<argon/libc.h>` можно включать в каждый: символы слабые.

Отдельный приём — один исходник, который собирается и как приложение, и как часть
ядра. Так сделан файловый менеджер: с `AG_BUILTIN` он часть образа системы и
команда `fm`, без него — обычный `.AXE`.

```c
#ifndef AG_BUILTIN
AG_APP("FM", "1.0", "argon", 0);      /* заголовок только у приложения */
#endif

#ifdef AG_BUILTIN                     /* и точка входа под своим именем */
#define FM_ENTRY ag_fm_main
#else
#define FM_ENTRY ag_main
#endif
```

Смысл не в экономии кода, а в проверке: встроенный вариант ходит через ту же
таблицу ABI, что и загруженный. Если работает встроенный — работает загруженный,
и контракт используется, а не обходится. Единственная разница, о которой надо
знать: в сборке ядра есть настоящая libc, поэтому `libc.h` отдаёт её функции
(`AG_HAVE_LIBC`), а `AG_HOT_RODATA` ничего не означает — размещением в образе
системы распоряжается её собственный скрипт линковки.
